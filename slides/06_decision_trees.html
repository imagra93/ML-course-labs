Decision Trees: Example of Decision Trees.

A tree predicts by asking a sequence of yes/no questions about single features until it reaches a leaf that holds a prediction.

CART (Classification And Regression Trees, Breiman et al. 1984) is the standard algorithm to grow them, and it is what scikit-learn implements.

A small tree is just a set of if / else rules: easy to explain to anyone.

Decision Trees: General idea

  • Root node: entire population.
  • Splitting: divides a node into sub-nodes (depends on the variable and its type).
  • Decision node: can be split.
  • Leaf node: terminal node.
  • Classification → probability of each class, from the population of the leaf node.
  • Regression → the mean of the leaf population.
$$h(\bx)=\sum_{\ell=1}^Lc_\ell\,\mathbb 1[\bx\in R_\ell]\qquad\text{(piecewise constant)}$$

Decision Trees: What a leaf predicts

Given the examples in a leaf, the constant $c$ that minimizes the loss on them is:

  • Squared error (regression) → the mean.
  • Absolute error → the median.
  • 0–1 loss (classification) → the majority class.
  • Log-loss → the class proportions $\hat p_k=N_k/N$ (what predict_proba returns).

Proof for the mean. Minimize $\sum_i(y^{(i)}-c)^2$ over $c$:

$$\frac{d}{dc}\sum_i\big(y^{(i)}-c\big)^2=-2\sum_i\big(y^{(i)}-c\big)=0\ \Rightarrow\ c=\frac1N\sum_iy^{(i)}=\bar y$$

For the majority class: predicting class $k$ is wrong for a fraction $1-p_k$ of the leaf, smallest when $p_k$ is largest.

No gradient descent here: the structure is found by a greedy search.

Decision Trees: Entropy

Entropy measures the uncertainty (or impurity) of a set of examples. For a dataset $S$ with $k$ classes:

$$H(S)=-\sum_{i=1}^kp_i\log_2(p_i)$$
  • $p_i$ = proportion of examples in class $i$.
  • $H(S)$ = entropy of dataset $S$.

If all examples are in one class: $H(S)=0$ (pure).
If examples are evenly split across classes: $H(S)$ is maximized.

If the dataset has 8 Yes and 8 No:

$$p_{\text{Yes}}=\tfrac{8}{16}=0.5,\ p_{\text{No}}=0.5\ \Rightarrow\ H(S)=-(0.5\log_20.5+0.5\log_20.5)=1$$

Decision Trees: Information Gain

When splitting on an attribute $A$, entropy usually decreases. The information gain (IG) is the reduction in entropy:

$$IG(S,A)=H(S)-\sum_{v\in\text{Values}(A)}\frac{|S_v|}{|S|}H(S_v)$$
  • $S_v$ = subset of $S$ where attribute $A=v$.
  • Weighted sum = expected entropy after splitting on $A$.
  • $IG(S,A)$ = how much information we gain about the class by splitting on $A$.

The decision tree picks the attribute with the highest information gain.

Each child's entropy is weighted by its size: a tiny pure child is not worth much.

Gini = the probability that two examples drawn at random from the node have different labels ($P(\text{same})=\sum_kp_k^2$). It is the CART default: a bit cheaper, no logarithm.

Entropy = expected number of bits to encode the label.

In practice Gini and entropy give almost the same trees.

Decision Trees: Choosing a split

$$\Delta I(j,s)=I(S_t)-\Big(\frac{N_L}{N_t}I(S_L)+\frac{N_R}{N_t}I(S_R)\Big)$$

Parent impurity minus the size-weighted impurity of the children. With entropy, $\Delta I$ is the information gain.

Decision Trees: Why not misclassification error?

A node with 400 A and 400 B. Two candidate splits:

Split 1Split 2
(300 A, 100 B) | (100 A, 300 B)(200 A, 400 B) | (200 A, 0 B)

Misclassification: split 1: $\frac12\cdot\frac14+\frac12\cdot\frac14=0.25$. Split 2: $\frac{600}{800}\cdot\frac13+\frac{200}{800}\cdot0=0.25$. A tie.

Gini: split 1: $2\cdot\frac34\cdot\frac14=0.375$ each → 0.375. Split 2: $\frac{600}{800}\cdot2\cdot\frac13\cdot\frac23+0=0.333$. Split 2 wins: it created a pure node.

Misclassification is piecewise linear in $p$, so many useful splits don't change it. Gini and entropy are strictly concave: by Jensen's inequality, any split that changes the class proportions strictly lowers the weighted impurity.

Regression trees. With variance as impurity, $\ N_t\,\Delta I_V=\mathrm{SSE}(S_t)-\big[\mathrm{SSE}(S_L)+\mathrm{SSE}(S_R)\big]$: maximizing the variance decrease is exactly reducing the tree's squared error. Each extra level can double the number of steps of the prediction.

Decision Trees: Algorithm.

Begin the tree with the root node $S$, which contains the complete dataset, and then:

  • Step 1: find the best attribute (in terms of information gain) in the dataset.
  • Step 2: divide $S$ into subsets that contain the possible values for the best attribute.
    • Note: there are other criteria, like the Gini index.
  • Step 3: generate the tree node that contains the best attribute.
  • Step 4: recursively make new decision trees using the subsets created in step 2. Continue until:
    • all matching records have the same output value,
    • data points are identical on the remaining attributes.
grow(S, depth):
  if stop(S, depth):       # pure, too small, max_depth
    return Leaf(value(S))
  for each feature j, threshold s:
    score ΔI(j, s)
  (j*, s*) = argmax ΔI
  return Node(j*, s*,
      grow(S_left,  depth + 1),
      grow(S_right, depth + 1))
$$\text{Gini}=1-\sum_{k=1}^Kp_k^2$$

Greedy: each split is the best one-step choice, never revisited. The optimal tree is NP-hard. A worked example.

  • Grown until every leaf is pure, a tree reaches zero training error and memorizes the noise.

Decision Trees: Regularization.

  • Define a maximum depth (lower than $m-1$).
    • Many use 10 as an absolute maximum.
  • Do not split if the information gain is less than a threshold (min_impurity_decrease), or a node is too small (min_samples_leaf).
  • Pruning. This makes the model more understandable and, perhaps, more accurate on fresh data. For example:
    • While the number of leaves exceeds the desired number: find the twig with the least information gain and collapse it.
    • Prune the tree to maximize classification performance on a validation set.

Cost-complexity pruning (CART's own method): grow a big tree $T_0$, then pick the subtree minimizing

$$R_\alpha(T)=R(T)+\alpha\,|T|$$

$R(T)$ = training error, $|T|$ = number of leaves. Regularization again: fit + $\alpha$ × complexity. Choose $\alpha$ (ccp_alpha) by cross-validation.

Decision Trees: Pros and Cons.

Advantages:

  • No assumptions about the spatial distribution and the classifier structure.
  • Less effort for data preparation during pre-processing.
  • A decision tree does not require normalization of data (only the order of values matters).
  • It can capture non-linear relationships and interactions.
  • Very intuitive and easy to explain to technical teams as well as stakeholders.

Disadvantages:

  • A small change in the data can cause a large change in the structure of the tree: instability.
  • Training can take longer than simpler models.
  • Very prone to overfitting:
    • with "m−1" splits you learn your data.
  • Can't extrapolate beyond the training range.

Fix for the variance: average many trees (next chapter).
