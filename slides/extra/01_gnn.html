Graph neural networks

imanolgranada@gmail.com

Where we are

Every architecture of the course builds in an assumption about the shape of the data. A CNN knows which pixels are neighbours, an RNN which word comes next, a transformer lets every token talk to every other.

Many data have none of these shapes: atoms joined by bonds, papers citing papers, claims that share a phone number. The neighbours are given by the data, and every node has a different number of them.

Graph neural network (GNN): a network whose layers update each node's vector from its neighbours' vectors, with the same weights at every node.

Four parts: A graphs as data, B message passing and the GCN with numbers, C variants and limits (spectral view, over-smoothing, GraphSAGE, GAT, GIN, the WL test), D graph- and edge-level tasks and practice. It ends with the Extra 1 lab.

Graphs are everywhere

Molecules

nodes atoms · edges bonds · task is it toxic, soluble, active? (one label per graph). A GNN found the antibiotic halicin (2020).

Social networks

nodes users · edges friendships, follows · task suggest a friend (edge), flag a bot (node).

Citation networks

nodes papers · edges citations · task the topic of each paper (node). Cora, in the lab.

Road networks

nodes road segments · edges connections · task travel time. Google Maps' arrival times use a GNN (2021).

Insurance claims

nodes claims, people, cars, workshops · edges "shares" · task fraud rings: suspicious only together.

Recommenders

nodes users and items · edges clicks, purchases · task the next click (edge). Pinterest: 3 billion nodes.

Anatomy of a graph

$G=(V,E)$: $n$ nodes and $|E|$ edges. Here $n=5$, $|E|=5$: a triangle with a tail.

Adjacency $\bA\in\{0,1\}^{n\times n}$: $A_{uv}=1$ if $u$–$v$ is an edge. Undirected graph: $\bA=\bA^\top$.

Neighbourhood $\Nb(v)$ and degree $d_v=|\Nb(v)|=\sum_uA_{vu}$, the row sums of $\bA$. Degree matrix $\bD=\mathrm{diag}(d_1,\dots,d_n)$.

Node features $\bX\in\R^{n\times d}$, one row per node: rows are examples, as in the whole course.

Optional extras: edge features $\mathbf e_{uv}$ (bond type, distance), directed or weighted edges, graph-level features. In code a graph is a list of edges, not an $n\times n$ matrix: real graphs are sparse (Cora: 0.14 % of the entries of $\bA$ are 1).

Three kinds of task

Node level

One prediction per node. The topic of a paper, is this account a bot, is this claim part of a fraud ring.

Edge level

One prediction per pair of nodes. Will these users connect, do these two drugs interact, which product is clicked next.

Graph level

One prediction per graph. Is this molecule toxic, what is its energy, which class is this 3-D shape.

Transductive: the test nodes are in the graph during training, only their labels are hidden (Cora). Inductive: new nodes or new graphs at test time (a new molecule, a new claim). The second needs a model of the neighbourhood, not a vector memorised per node.

The order of the nodes is arbitrary

To store a graph we number its nodes, and the numbering is arbitrary: $n!$ choices. $5!=120$ here, $34!\approx3\times10^{38}$ for a 34-person club.

Renumbering = a permutation matrix $\mathbf P$. The features become $\mathbf P\bX$, the adjacency $\mathbf P\bA\mathbf P^\top$: different matrices, the same graph.

Naive idea: flatten $\bA$ and $\bX$ into one vector and use an MLP.

  • a different output for each numbering of the same graph
  • the input size fixes $n$: no graphs of other sizes
  • $n^2$ inputs, almost all zeros

An MLP could learn the symmetry from data, but it would need to see every graph under many of its $n!$ numberings. Better to build it into the architecture, as a CNN builds in translations.

Equivariance and invariance

A layer that computes one vector per node must be equivariant: renumber the input and the output rows are renumbered the same way.

$$f(\mathbf P\bX,\ \mathbf P\bA\mathbf P^\top)=\mathbf P\,f(\bX,\bA)$$

A prediction for the whole graph must be invariant: $\ g(\mathbf P\bX,\mathbf P\bA\mathbf P^\top)=g(\bX,\bA)$.

Recipe: stack equivariant layers, end with an invariant readout (sum, mean or max over the nodes). It is the CNN recipe: convolutions are equivariant to shifts, global pooling makes the class invariant.

Building block: sum, mean and max of a set of vectors do not depend on the order of the set, and they work for any number of vectors. They will aggregate the neighbours.

The idea: message passing

One layer turns the node vectors $\bh_v^{(k)}$ into $\bh_v^{(k+1)}$. Each node, in parallel:

$$\bh_v^{(k+1)}=\mathrm{UPD}\Big(\bh_v^{(k)},\ \underset{u\in\Nb(v)}{\mathrm{AGG}}\ \mathrm{MSG}\big(\bh_u^{(k)},\bh_v^{(k)}\big)\Big)$$

MSG: what $u$ tells $v$; often just $\bh_u\bW$.

AGG: sum, mean or max. Permutation invariant, any number of neighbours.

UPD: combine with $v$'s own vector; a non-linearity or an MLP.

Same functions at every node: weight sharing, like one convolution filter slid over the whole graph. $\bh_v^{(0)}=\bx_v$, the input features.

Neighbour sum = multiply by $\bA$

Node C sums its neighbours' features:

$$\sum_{u\in\Nb(C)}\bx_u=\bx_A+\bx_B+\bx_D=(1,0)+(0,1)+(2,0)=(3,1)$$

Row $v$ of $\bA\bX$ is $\sum_uA_{vu}\,\bx_u$. Since $A_{vu}=1$ only for the neighbours, it is exactly that sum:

$$(\bA\bX)_v=\sum_{u\in\Nb(v)}\bx_u$$

All nodes at once: A $(1,2)$, B $(2,1)$, C $(3,1)$, D $(1,3)$, E $(2,0)$. With a sparse $\bA$ the cost is $O(|E|\,d)$, not $O(n^2d)$.

Two problems, two fixes

1 · A node forgets itself. Row C of $\bA\bX$ has no $\bx_C$. Fix: add self-loops, $\tA=\bA+\bI$, with degrees $\tilde d_v=d_v+1$.

2 · Hubs explode. A node with 1,000 neighbours gets a sum 1,000 times larger than a leaf, and the gap grows with every layer. Fix: normalise by the degree.

  • mean: $\tD^{-1}\tA$, row $v$ divided by $\tilde d_v$
  • symmetric: $\hA=\tD^{-1/2}\tA\tD^{-1/2}$, edge $u$–$v$ weighted $1/\sqrt{\tilde d_u\tilde d_v}$. A popular neighbour counts less for each of its many neighbours.

With the mean, A and B both get $(0.667, 0.667)$: they average the same three nodes $\{A,B,C\}$, so their different features are already blurred together. Remember it for over-smoothing.

The GCN layer (Kipf & Welling, 2017)

$$\bH^{(k+1)}=\sigma\big(\hA\,\bH^{(k)}\,\bW^{(k)}\big),\qquad \hA=\tD^{-1/2}(\bA+\bI)\,\tD^{-1/2}$$

$\bH\bW$: the same linear map for every node, a shared per-node layer (like a $1\times1$ convolution). $d\times d'$ parameters, whatever the graph size.

$\hA\,(\cdot)$: each node takes a weighted average of its own and its neighbours' transformed vectors. No parameters: the graph decides who mixes with whom.

$\sigma$: ReLU between layers. Two or three layers; the last one gives class scores, with a softmax for node classification.

$$\text{one node: }\ \bh_v^{(k+1)}=\sigma\Big(\sum_{u\in\Nb(v)\cup\{v\}}\frac{1}{\sqrt{\tilde d_u\,\tilde d_v}}\;\bh_u^{(k)}\bW^{(k)}\Big)$$

One GCN layer with numbers

Toy graph, $\bX$ as before, $\ \bW=\begin{pmatrix}1&-1\\0.5&1\end{pmatrix}$, ReLU. Follow node C:

Row C of $\hA$: C keeps $1/\tilde d_C=1/4=0.25$ of itself; each neighbour gets $1/\sqrt{3\cdot4}=0.289$ (A, B and D have $\tilde d=3$). E is not a neighbour: 0.

$(\hA\bX)_C=0.289\,(1,0)+0.289\,(0,1)$

$\qquad\quad+\,0.25\,(1,1)+0.289\,(2,0)=(1.116,\ 0.539)$

A and B get the same row $(0.622, 0.622)$: same closed neighbourhood, same weights.

$(1.116,\ 0.539)\,\bW=(1.116+0.270,\ -1.116+0.539)$

$\qquad=(1.385,\ -0.577)$

$(\hA\bX)\bW=\hA(\bX\bW)$: libraries compute $\bX\bW$ first, cheaper when $d'\lt d$.

$\bh_C'=\mathrm{ReLU}(1.385,\,-0.577)=(1.385,\ 0)$.

All rows: A $(0.933, 0)$, B $(0.933, 0)$, C $(1.385, 0)$, D $(1.508, 0.150)$, E $(1.316, 0.184)$.

Stack a second layer with its own $\bW^{(2)}$ and C hears from E too.

More layers, more hops

After one layer $\bh_v$ depends on $v$ and its neighbours; after two, on the neighbours of the neighbours. After $K$ layers: the $K$-hop neighbourhood, the receptive field of the node, as in a CNN.

The graph is Zachary's karate club (1977): 34 members, 78 friendships. Node 16 is its most remote member: 3 layers reach 18 members, 5 reach all 34. For the average member, 3 layers already reach 29 of the 34.

Social and citation graphs are small worlds: a few hops cover a large fraction of the graph. That is one reason GNNs are shallow (2 or 3 layers), while CNNs need dozens of layers to see the whole image.

The other reason, over-smoothing, is in Part C.

The computation tree of one node

Unroll two layers for node C. Each node in the tree is computed from its own closed neighbourhood one level down; the leaves are the raw features $\bx$.

Every node has its own tree, but all trees use the same $\bW^{(1)}$ at the bottom and the same $\bW^{(2)}$ at the top: weight sharing.

The tree grows like $d^K$: C appears 4 times, and in a social graph a 3-layer tree can contain millions of leaves. This neighbour explosion is why large graphs are trained on sampled trees (GraphSAGE, Part C).

A mini-batch on a big graph = a few target nodes plus their $K$-hop trees. A GNN only ever sees a node through its tree: if two nodes have identical trees, it cannot tell them apart.

Training: few labels, all the nodes

Semi-supervised node classification. The loss uses the labelled nodes $V_L$ only:

$$J=-\frac{1}{|V_L|}\sum_{v\in V_L}\log\hat p_{v,\,y_v}$$

The forward pass runs on every node: the unlabelled ones pass their features on, and backpropagation goes through them.

Cora: 2,708 papers, 5,278 citations, a 1,433-word bag of words per paper, 7 topics. Only 140 labels (20 per topic), 500 for validation, 1,000 for test.

Features alone (MLP) or the graph alone (label propagation) do poorly. Together they work: the topic of a paper is predicted from its words and those of the papers around it.

Test accuracy on Cora as reported in the GCN (Kipf & Welling, 2017) and GAT (Veličković et al., 2018) papers. The lab, on a short CPU budget, gets 57.3, 73.1, 81.0 and 81.7 %.

The karate club: a GCN with two labels

3-layer GCN $34\to4\to4\to2$ with tanh, then a linear classifier. Input: a one-hot node id, so no features at all. Labels: only member 0 (the instructor) and member 33 (the president).

Epoch 0, random weights: the embeddings are tiny (the plot zooms in) but already roughly group the two factions, because $\hA$ averages over neighbourhoods. Only the classifier is random: 16 of 32. Training first moves the line, then spreads the groups.

The Laplacian measures smoothness

Graph Laplacian $\bL=\bD-\bA$. For a signal $\bx$ with one number per node:

$$\bx^\top\bL\bx=\sum_{(u,v)\in E}(x_u-x_v)^2$$

Proof: $\bx^\top\bD\bx=\sum_vd_vx_v^2$ counts each edge's $x_u^2+x_v^2$ once, and $\bx^\top\bA\bx=2\sum_Ex_ux_v$. Toy graph, $\bx=(1,3,2,0,4)$: $4+1+1+4+16=26$.

Small when neighbours have similar values: a smooth signal.

The eigenvectors $\mathbf u_k$ of $\bL$ ($\lambda_0=0\le\lambda_1\le\dots$) are the graph's Fourier modes: $\lambda_k=\mathbf u_k^\top\bL\mathbf u_k$ is how rough mode $k$ is. On a path they are exactly cosines.

The second eigenvector, the Fiedler vector (mode 1 here, $\mathbf u_2$ in the lab), is the smoothest non-constant signal: its sign cuts the graph where few edges cross. On the karate club it predicts the split for 32 of 34 members.

A GCN layer is a low-pass filter

$\hA=\bI-\tilde\bL_{\text{sym}}$ shares its eigenvectors with the normalised Laplacian (with self-loops), whose eigenvalues lie in $[0,2)$.

So multiplying by $\hA$ multiplies the component of the signal along mode $\lambda$ by $(1-\lambda)$. Smooth modes pass, rough ones are damped: a low-pass filter.

A GCN layer = a learned feature map $\bW$ + a fixed low-pass filter on the graph. It helps when labels are smooth over the graph: homophily. In Cora 81 % of the citations join papers of the same topic.

$K$ layers apply $(1-\lambda)^K$: everything but the smoothest direction fades. That is over-smoothing, next slide.

Why the self-loops: without them $\lambda$ can reach 2, where $|1-\lambda|^K=1$: the roughest modes would pass undamped, flipping sign at every layer. With them the spectrum stays well below 2 (grey band).

History: spectral CNNs (2014) learned a filter per eigenvalue, $O(n^3)$; ChebNet (2016) used polynomials of $\bL$; GCN (2017) kept degree 1 and added the self-loops.

Over-smoothing: deep GCNs make every node alike

Start from random node values and multiply by $\hA$ again and again (a GCN without weights). Each node converges to $\sqrt{\tilde d_v}$ times one common number: the nodes become indistinguishable.

With weights it happens too: in the lab a plain GCN on Cora scores 81 % with 2 layers, 76 % with 4 and 20 % with 8. Residual connections keep 76 % at 8.

Fixes: residual connections $\bh+f(\bh)$; jumping knowledge (concatenate every layer's output); normalisation (PairNorm); DropEdge; or decouple: a few propagation steps on precomputed features (SGC, APPNP).

Two more classic limits: over-squashing, exponentially many nodes squeezed into one fixed-size vector; heterophily, neighbours that differ, where smoothing destroys the signal.

GraphSAGE: sample, aggregate, concatenate

$$\bh_v'=\sigma\Big(\big[\,\bh_v\ \big\|\ \underset{u\in S(v)}{\mathrm{mean}}\ \bh_u\,\big]\,\bW\Big)$$

Concatenate (Hamilton et al., 2017): "me" and "my neighbours" get separate weights; GCN mixes them in one average. It helps when neighbours differ from the node.

Sample: $S(v)$ = a fixed number of random neighbours per layer (e.g. 25, then 10). A target costs at most $25\cdot10=250$ nodes whatever the degrees, so mini-batches work on huge graphs. PinSage (Pinterest, 2018): 3 billion nodes, 18 billion edges.

Inductive: it learns how to aggregate, not one vector per node. A node that appears after training (a new user, a new claim) gets an embedding from its neighbourhood.

Other aggregators: max of an MLP of the neighbours, an LSTM over a random order.

GAT: attention over the neighbours

GCN fixes the weight of edge $u$–$v$ from the degrees. GAT (Veličković et al., 2018) learns it from the features of both ends:

$$e_{vu}=\mathrm{LeakyReLU}\big(\mathbf a^\top[\,\bh_v\bW\,\|\,\bh_u\bW\,]\big)$$
$$\alpha_{vu}=\frac{e^{e_{vu}}}{\sum_{w\in\Nb(v)\cup\{v\}}e^{e_{vw}}},\qquad\bh_v'=\sigma\Big(\sum_{u}\alpha_{vu}\,\bh_u\bW\Big)$$

The softmax runs over the neighbours only: attention with the graph as a mask. Multi-head: 8 heads, concatenated (Cora).

Numbers: $\bh\bW=\bX\bW$ from the GCN slide, $\mathbf a=(0.2,0\,;\,0.5,1)$. On Cora the learned weights are almost uniform, so GAT ≈ GCN there (lab: 81.7 vs 81.0 %). Subtlety: with the monotonic LeakyReLU outside, every node ranks its neighbours in the same order ("static" attention); GATv2 (2022) fixes it.

A transformer is a GNN on the complete graph

who are the neighboursweight of $u$'s message to $v$
GCNthe graph's edges$1/\sqrt{\tilde d_u\tilde d_v}$, fixed
GATthe graph's edgessoftmax of a learned score
transformerevery tokensoftmax of $\bq_v\cdot\bk_u/\sqrt{d_k}$

Self-attention is message passing on the complete graph. It is permutation equivariant, which is exactly why a transformer needs positional encodings: the complete graph says nothing about who is next to whom.

Graph transformers (Graphormer, GPS) attend between all nodes and put the graph back as encodings: Laplacian eigenvectors as positions, shortest-path distances as an attention bias. Good against over-squashing; the price is $O(n^2)$.

Sum, mean or max?

mean sees the proportions of the neighbours, max only which values occur, sum the values with their counts (the multiset).

Pair 3 fools the sum of the raw numbers, $1+3=2+2$. Not if each value first goes through a non-linear $f$: $f(1)+f(3)\ne 2f(2)$. With the right $f$, $\sum_uf(\bh_u)$ is injective on multisets (Xu et al., 2019).

GIN, the Graph Isomorphism Network, puts an MLP after the sum:

$$\bh_v'=\mathrm{MLP}\Big((1+\epsilon)\,\bh_v+\sum_{u\in\Nb(v)}\bh_u\Big)$$

Mean is fine when the degree is noise (how many papers cite you), max for "is there any …" features. Sum when counts matter: two oxygen atoms are not one.

How powerful is message passing? The WL test

1-WL colour refinement (Weisfeiler and Lehman, 1968). Start with one colour for every node, then repeat:

new colour of $v$ = a new name for (colour of $v$, multiset of its neighbours' colours)

Different colour histograms ⇒ the graphs are different. Equal histograms ⇒ maybe the same.

A message-passing GNN runs the same algorithm with a learned function instead of renaming. So its vector for $v$ can depend only on $v$'s WL colour: nodes or graphs that 1-WL cannot tell apart get the same embedding in every message-passing GNN (Xu et al.; Morris et al., 2019).

GIN's sum + MLP is injective, so GIN is as powerful as 1-WL. GCN (weighted mean) and GraphSAGE-mean are weaker.

What message passing cannot see

Two triangles and one hexagon: 6 nodes, 6 edges, every node has 2 neighbours, each with 2 neighbours… In every round all nodes keep one colour.

So GCN, GAT, GraphSAGE and GIN give the two graphs identical embeddings, whatever the weights. The lab checks it.

Yet one has triangles and the other a 6-ring, and a chemist cares about rings. In general message passing cannot count triangles, find cycles of a given length, or compute distances beyond its depth.

Fixes: add structural features (degree, cycle counts, Laplacian eigenvectors as positions); random features or node ids (break the symmetry, invariant only on average); higher-order GNNs ($k$-WL, subgraph GNNs); graph transformers with structural encodings.

Graph-level tasks: readout and batching

Readout: $\ \bh_G=\sum_{v\in G}\bh_v^{(K)}$ (or mean, or max), then an MLP. Invariant by construction. GIN concatenates the readouts of every layer, to keep shallow and deep features.

Example: MUTAG, 188 molecules (about 18 atoms each, 7 atom types), mutagenic or not. With so few graphs, report the mean ± std of a 10-fold cross-validation: the std is several points.

Batching: put $B$ graphs side by side as one big graph with no edges between them. Its adjacency is block diagonal, so messages never cross from one graph to another.

A batch vector says which graph each node belongs to; the readout sums per segment. No padding: each graph costs exactly its own nodes and edges.

Edge-level tasks: link prediction

Score a pair from the two node vectors: $\ \hat p_{uv}=\sigma(\bh_u^\top\bh_v)$, or an MLP on $[\bh_u\|\bh_v]$ or on $\bh_u\odot\bh_v$.

Training: positives = existing edges; negatives = random pairs (negative sampling, fresh every epoch); binary cross-entropy. Metric: ROC-AUC, or hits@K and MRR against many negatives.

The trap. Split the edges into train, validation and test, and remove the validation and test edges from the message-passing graph too. Otherwise $u$ and $v$ exchange messages through the very edge we ask about, and the score is inflated: in the lab, ROC-AUC 0.92 done right, 0.97 with the leak.

Typed edges (a person drives a car, a claim involves a workshop) need one $\bW$ per relation: relational GNNs (R-GCN), heterogeneous graphs.

In code: gather, then scatter

A graph in code is edge_index: a $2\times|E|$ integer tensor, one column per directed edge (sources, targets). One GCN layer, no $n\times n$ matrix:

src, dst = edge_index            # with self-loops, both directions
deg  = torch.bincount(dst, minlength=n).float()
norm = (deg[src] * deg[dst]).rsqrt()   # 1/√(d̃ᵤ d̃ᵥ)
msg  = (h @ W)[src] * norm[:, None]    # gather: one row per edge
out  = torch.zeros(n, W.shape[1])
out.index_add_(0, dst, msg)            # scatter: sum at the target

Time $O(|E|\,d)$, memory $O(|E|+nd)$. A dense $\hA$ for Cora would have 7.3 million entries for 13 thousand non-zeros.

Libraries do exactly this. PyTorch Geometric: GCNConv(16, 7)(h, edge_index); also SAGEConv, GATConv, GINConv. DGL is the other big library.

Node classification in PyTorch Geometric

import torch, torch.nn.functional as F
from torch_geometric.datasets import Planetoid
from torch_geometric.nn import GCNConv

data = Planetoid("data", "Cora")[0]   # x, edge_index, y, masks

class GCN(torch.nn.Module):
    def __init__(self, d_in, d_hid, n_cls):
        super().__init__()
        self.c1 = GCNConv(d_in, d_hid)
        self.c2 = GCNConv(d_hid, n_cls)
    def forward(self, x, ei):
        x = F.dropout(x, 0.5, self.training)
        x = F.relu(self.c1(x, ei))
        x = F.dropout(x, 0.5, self.training)
        return self.c2(x, ei)            # class scores

model = GCN(1433, 16, 7)
opt = torch.optim.Adam(model.parameters(), lr=0.01,
                       weight_decay=5e-4)
for epoch in range(200):
    model.train(); opt.zero_grad()
    out = model(data.x, data.edge_index)        # all nodes
    m = data.train_mask                         # 140 labels
    F.cross_entropy(out[m], data.y[m]).backward()
    opt.step()

One graph, one batch: Cora fits in memory, so every step is full batch.

Forward on all nodes, loss on 140. The masks select the labelled, validation and test nodes.

Strong regularisation: dropout 0.5 and weight decay, because 140 labels are overfitted in a few dozen epochs. Pick the epoch on val_mask.

16 hidden units, 2 layers: about 23 thousand parameters, 99 % of them in the first layer's $1433\times16$ matrix.

Test accuracy ≈ 81 %. The lab builds this layer from scratch first, then checks that GCNConv gives the same numbers.

The topic in one slide

A · Graphs as data

  • $G=(V,E)$, features $\bX$ ($n\times d$), adjacency $\bA$, degrees $\bD$
  • node-, edge- and graph-level tasks; transductive or inductive
  • the node order is arbitrary: equivariant layers, invariant readout

B · Message passing and the GCN

  • $\bh_v'=\mathrm{UPD}(\bh_v,\mathrm{AGG}_{u\in\Nb(v)}\mathrm{MSG}(\bh_u,\bh_v))$
  • GCN: $\sigma(\hA\bH\bW)$, $\hA=\tD^{-1/2}(\bA+\bI)\tD^{-1/2}$
  • $K$ layers = $K$ hops; loss on labelled nodes, forward on all

C · Variants and limits

  • $\hA$ is a low-pass filter: deep GCNs over-smooth
  • SAGE: concat + sampling; GAT: learned edge weights; transformer = complete graph
  • GIN (sum + MLP) = 1-WL; two triangles = one hexagon for every MPNN

D · Tasks and practice

  • graphs: readout + block-diagonal batching; edges: $\sigma(\bh_u^\top\bh_v)$, negatives
  • hide test edges from message passing
  • code: gather + scatter on edge_index, $O(|E|d)$; baselines first
