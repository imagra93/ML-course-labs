Problems with LSTMs

  • Inputs are sequential: step $t$ must wait for step $t-1$, so nothing runs in parallel.
  • Information from far away must survive many steps, and it fades.
  • The whole input is squeezed into one fixed-size state.

What we want:

  • handle inputs of different lengths,
  • parallel processing of the entire input,
  • shared parameters (like CNNs),
  • any position reachable from any other in one step.

Attention Is All You Need

Vaswani, Shazeer, Parmar, Uszkoreit, Jones, Gomez, Kaiser, Polosukhin · 2017

The paper that introduced the transformer: no recurrence, no convolution, only attention. Behind GPT, BERT, translation, speech (Whisper) and vision (ViT). Two labs close this chapter: Lab 14 (text generation with GPT-2) and Lab 15 (RAG: search and grounded answers).

Why attention: the bottleneck

Before attention, sequence models compressed an entire input sequence into a single fixed-size vector before decoding it. Long sequences lost information by the time they reached the output.

Attention (Bahdanau 2014) fixes this by letting the decoder look back at every input position every time it produces an output, and decide how much each one matters.

Attention in translation: a soft alignment

When writing each Spanish word, the decoder computes a weight for every English word, then reads a weighted average of their encoder states.

$$\bc_t=\sum_j\alpha_{tj}\,\bh_j,\qquad\sum_j\alpha_{tj}=1$$

Nobody tells the network that "negro" goes with "black". The weights are learned end to end, only from pairs of sentences.

The transformer takes this idea to its limit: attention everywhere, and no recurrence at all.

Attention: a soft dictionary lookup

A Python dictionary returns the value whose key exactly matches the query. Attention returns a weighted mix of all the values, weighted by how well each key matches:

  • Query $\bq$: what am I looking for?
  • Keys $\bk_j$: what does each position offer?
  • Values $\mathbf v_j$: what does each position pass on?
$$\alpha_j=\mathrm{softmax}_j\big(\bq^\top\bk_j\big),\qquad\text{output}=\sum_j\alpha_j\,\mathbf v_j$$

The weights are positive and sum to 1: the output is a linear combination of the values.

Everything is differentiable, so the queries, keys and values can be learned by backprop.

Toy numbers: 2-dimensional queries and keys. (The factor $1/\sqrt{d_k}$ is explained a few slides ahead.)

Attention with numbers

Three tokens with 2-dimensional keys and values. We compute the new vector for "pizza", whose query is $\bq=(2,1)$:

1 · Compare the query with every key (dot product, divided by $\sqrt{d_k}=\sqrt2$):

$$\text{scores}=\tfrac{1}{\sqrt2}\big(\bq\cdot\bk_{\text I},\ \bq\cdot\bk_{\text{love}},\ \bq\cdot\bk_{\text{pizza}}\big)=\tfrac1{\sqrt2}(2,1,3)$$

2 · Normalise with a softmax: positive weights that sum to 1.

$$\boldsymbol\alpha=\mathrm{softmax}(1.41,\,0.71,\,2.12)=(0.28,\,0.14,\,0.58)$$

3 · Mix the values with these weights:

$$\text{out}=0.28\binom10+0.14\binom01+0.58\binom{0.5}{0.5}=\binom{0.57}{0.43}$$

Every token does this at the same time, each with its own query. Where do these keys, values and queries come from? Next slide.

Where do queries, keys and values come from?

On the previous slide the numbers were given. In a transformer every token computes its own query, key and value from its embedding $\bx_i$ (a row vector), with three learned matrices:

$$\bq_i=\bx_i\bW_Q,\qquad\bk_i=\bx_i\bW_K,\qquad\bv_i=\bx_i\bW_V$$

The same three matrices for every token. They are the parameters that training adjusts.

Check one product. "pizza" has $\bx=(1,1,1)$, so $\bx\bW_Q$ is the sum of the rows of $\bW_Q$: $(1,0)+(0,1)+(1,0)=(2,1)$, the query of the previous slide. The same matrices give "I" and "love" their keys and values too.

"Self"-attention: queries, keys and values all come from the same sentence.

Why two matrices for Q and K? "What I look for" and "what I offer" differ: a verb looks for its subject, a noun offers itself as one. With a single matrix, $\text{score}(i,j)=\text{score}(j,i)$ always.

Real sizes, GPT-2 small: $\bx_i$ has $d=768$ numbers and each head has its own $768\times64$ matrices.

Self-attention: all tokens at once

1 · Score. How much token $i$ should look at token $j$:

$$\text{score}(i,j)=\frac{\bq_i\cdot\bk_j}{\sqrt{d_k}}$$

2 · Normalise. A softmax over $j$ turns each row of scores into weights that sum to 1:

$$\alpha_{ij}=\frac{e^{\,\text{score}(i,j)}}{\sum_{l=1}^ne^{\,\text{score}(i,l)}}$$

3 · Mix. The new vector of token $i$ is a weighted average of the values: $\ \bz_i=\sum_{j=1}^n\alpha_{ij}\,\bv_j$.

Stack the tokens as the rows of $\bX$ ($n\times d$): $\bQ=\bX\bW_Q$, $\bK=\bX\bW_K$, $\bV=\bX\bW_V$. Entry $(i,j)$ of $\bQ\bK^\top$ is $\bq_i\cdot\bk_j$, so the three steps become one line:

$$\mathrm{Attention}(\bQ,\bK,\bV)=\mathrm{softmax}\Big(\frac{\bQ\bK^\top}{\sqrt{d_k}}\Big)\bV$$

Example: $n=10$ tokens, $d=512$, $d_k=64$. $\bQ,\bK,\bV$ are $10\times64$, the scores $10\times10$, the output again $10\times64$. Cost $O(n^2d)$: twice the context, four times the work.

The whole attention matrix

Each row is one query: a probability distribution over the sentence. The red row is the one of the previous slide.

Each column shows who reads from that word. "animal" is read by "cross", "it" and "tired": the matrix captures who-relates-to-whom in the sentence.

A trained model has one such matrix per head and per layer: GPT-2 small has 12 × 12 = 144 of them for every input.

Why divide by $\sqrt{d_k}$?

The problem. A dot product adds up $d_k$ terms, so it grows with the dimension. Large scores make the softmax almost one-hot (right, red), and then its gradient is almost 0: attention stops learning.

How large? Suppose the components of $\bq$ and $\bk$ are independent, with mean 0 and variance 1:

$$\E[\bq^\top\bk]=\sum_{i=1}^{d_k}\E[q_i]\,\E[k_i]=0$$

expectation of a sum = sum of expectations; independent factors; every mean is 0

$$\mathrm{Var}(\bq^\top\bk)=\sum_{i=1}^{d_k}\mathrm{Var}(q_ik_i)=\sum_{i=1}^{d_k}\E[q_i^2]\,\E[k_i^2]=d_k$$

independent terms add their variances; each term has mean 0 and variance $1\cdot1$

So raw scores have standard deviation $\sqrt{d_k}$: 8 for $d_k=64$. Dividing by $\sqrt{d_k}$ brings the variance back to 1, whatever the dimension (blue). $\blacksquare$

Multi-head attention: several attentions in parallel

One head gives one weighted average per token: it cannot look at the previous word and at the subject at the same time. So we run $h$ heads, each with its own projections:

$$\mathrm{head}_i=\mathrm{Attention}\big(\bX\bW_Q^{(i)},\bX\bW_K^{(i)},\bX\bW_V^{(i)}\big)$$
$$\mathrm{MultiHead}(\bX)=\mathrm{Concat}(\mathrm{head}_1,\dots,\mathrm{head}_h)\,\bW_O$$

GPT-2 small: $d=768$, $h=12$ heads of $d_k=64$. Twelve heads of 64 have the same parameters and cost as one head of 768: the slices only split the work. $\bW_O$ mixes what the heads found.

Different heads, different jobs

One head alone gives one weighted average per token: it cannot look at the previous word and at the subject at the same time. With several heads, each builds its own pattern, and $\bW_O$ mixes their results. Researchers find heads like these (previous-token, coreference, "induction" heads that copy patterns) in trained language models.

Attention ignores word order

distance between the two "dog" vectors–

Attention compares every token with every token, but nothing in the formula says which word came first.

Shuffle the input words and the outputs are shuffled the same way, nothing else changes. "dog bites man" and "man bites dog" give each word the same vector. Attention is permutation-equivariant (a three-line proof in the notes).

An RNN got the order for free: it reads one word after another. A transformer reads all the words at once, so we must tell it where each word is.

The fix, on the next slide: add to each word a vector that encodes its position.

Positional encodings: tell the model where each word is

Before the first block, add to each token a vector that depends only on its position:

$$\text{input}_t=\text{embedding}(\text{token}_t)+PE(t)$$
$$PE_{(pos,\,2i)}=\sin\Big(\frac{pos}{10000^{2i/d}}\Big)$$$$PE_{(pos,\,2i+1)}=\cos\Big(\frac{pos}{10000^{2i/d}}\Big)$$

Sinusoidal (above, the original transformer): each pair of dimensions is a clock at its own speed. Fast clocks tell neighbours apart, slow clocks far positions; together they give every position a unique fingerprint (right). Moving $k$ positions turns every clock by a fixed angle, wherever you start: "3 words back" is easy to learn.

Learned: one trainable vector per position (GPT-2: 1,024 of them, hence its context limit). RoPE (Llama and most modern LLMs): rotate $\bq$ and $\bk$ by an angle that grows with the position, so their score depends only on the distance between the two tokens.

The causal mask: no peeking at the future

The mask is optional, but it is used where it does not make sense for a word to look at future words, because they are not available in reality: not for classifying a known sentence, but for next-word prediction.

$$\mathrm{softmax}\Big(\frac{\bQ\bK^\top}{\sqrt{d_k}}+\mathbf M\Big)\bV,\qquad M_{ij}=\begin{cases}0&j\le i\\-\infty&j\gt i\end{cases}$$

$e^{-\infty}=0$: future tokens get exactly zero weight. And one forward pass trains all $n$ next-token predictions of a sequence at once.

Self-attention in code

import math, torch

def self_attention(X, Wq, Wk, Wv, causal=False):
    Q, K, V = X @ Wq, X @ Wk, X @ Wv       # [n, dk] each
    S = Q @ K.T / math.sqrt(K.shape[-1])   # [n, n] scores
    if causal:                             # hide the future
        future = torch.triu(torch.ones_like(S), diagonal=1).bool()
        S = S.masked_fill(future, float("-inf"))
    A = S.softmax(dim=-1)                  # each row sums to 1
    return A @ V                           # [n, dv]: new vectors

X = torch.randn(10, 512)                   # 10 tokens, d = 512
Wq, Wk, Wv = (torch.randn(512, 64) / 512**0.5 for _ in range(3))
Z = self_attention(X, Wq, Wk, Wv, causal=True)   # [10, 64]

Everything of the last slides fits in a handful of lines: three projections, one scaled product, an optional mask, a softmax per row, and a weighted average of the values.

With a batch, the same code works on tensors $[B,n,d]$ (write K.transpose(-2, -1) for $\bK^\top$). Multi-head: reshape to $[B,h,n,d_k]$ and run all heads at once.

In practice: nn.MultiheadAttention, or F.scaled_dot_product_attention(Q, K, V, is_causal=True), which uses fast fused kernels (FlashAttention).

One transformer block: communicate, then think

Attention moves information between tokens. The MLP ($d\to4d\to d$ with GELU, chapter 1) then processes each token separately. The MLP holds two thirds of a block's parameters.

$$\bX\leftarrow\bX+\mathrm{MHA}\big(\mathrm{LN}(\bX)\big),\qquad\bX\leftarrow\bX+\mathrm{MLP}\big(\mathrm{LN}(\bX)\big)$$

Residual connections (chapter 4) add each result to its input, so the gradient has a direct path through all the blocks. LayerNorm (chapter 3) keeps each token's vector at a stable scale.

A block never changes the shape $n\times d$, so blocks are simply stacked: GPT-2 small has 12, GPT-3 has 96.

The original transformer: encoder and decoder

Built for translation (2017). The encoder reads the whole source sentence; the decoder writes the translation one token at a time.

  • Encoder blocks: full self-attention, every word sees every word.
  • Decoder blocks: masked self-attention (only the past), then cross-attention.

Cross-attention: queries from the decoder, keys and values from the encoder's output. It is the soft alignment of translation from Part A, inside the transformer:

$$\mathrm{softmax}\Big(\frac{\bQ_{\text{dec}}\,\bK_{\text{enc}}^\top}{\sqrt{d_k}}\Big)\bV_{\text{enc}}$$

The figure follows the paper, with "Add & Norm" after each sub-layer (post-norm). GPT-2 and most modern models put the LayerNorm before each sub-layer (pre-norm, previous slide): it trains more stably.

Tokens: how text becomes numbers

A transformer reads a sequence of token ids. What should a token be?

  • Words: hundreds of thousands of them, and a new word is unknown.
  • Characters: few symbols, but very long sequences, and attention costs $n^2$.
  • Sub-words (GPT's choice): frequent words are one token, rare words are split into pieces.

Byte-pair encoding (BPE) learns the sub-words: start from characters, count the adjacent pairs in a corpus, merge the most frequent pair into a new symbol, repeat. GPT-2 stops at 50,257 tokens. Nothing is ever unknown: in the worst case a word is spelled out.

GPT-2 in Lab 14: "Welcome to the deep learning class" is 6 words and 6 tokens. "Bienvenidos a la clase de aprendizaje profundo" is 7 words and 17 tokens: GPT-2 learned its merges on English text.

Language modelling: predict the next token

By the chain rule of probability, any sequence of tokens factorizes as

$$P(x_1,\dots,x_T)=\prod_{t=1}^TP(x_t\mid x_1,\dots,x_{t-1})$$

So the model only has to learn one thing: the next token given the previous ones. That is a classification over $|V|=50{,}257$ classes, with softmax and cross-entropy, exactly as in chapter 1.

Training minimizes the average of $-\log p$ over the tokens that really came:

$$J=-\frac1T\sum_{t=1}^T\log P(x_t\mid x_{\lt t})$$

Any text is training data: the targets are the inputs shifted by one (below). No labels are needed: the training is self-supervised.

Thanks to the causal mask, one forward pass over 6 tokens trains all 5 predictions at once.

GPT end to end: from text to the next token

Follow the shapes. Five tokens become a $5\times768$ matrix, one row per token. The 12 blocks mix the rows with attention and process each row with the MLP, but never change that shape. One product with $\bE^\top$ gives a score for each of the 50,257 tokens at every position.

Only the last row is turned into probabilities to choose the next token. The other rows are not wasted: during training each row predicts its own next token (the shifted targets of the language-modelling slide). After "The cat sat on the", GPT-2 spreads its probability over many plausible words: floor 7.6 %, bed 6.5 %, couch 5.4 %…

GPT: counting the parameters

Token + position embedding → $N$ identical blocks → final LayerNorm → linear layer to $|V|$ logits. Per block, ignoring biases and LayerNorms:

  • Attention: $\bW_Q,\bW_K,\bW_V,\bW_O$, each $d\times d$: $\ 4d^2$.
  • MLP with hidden size $4d$: $\ d\cdot4d+4d\cdot d=8d^2$.
  • Total: $12d^2$ per block.

GPT-2 small: $N=12$, $d=768$, $|V|=50{,}257$, 1,024 positions:

$$\underbrace{12\cdot12\cdot768^2}_{\text{blocks}}\approx84.9\text{M}+\underbrace{50{,}257\cdot768}_{\text{token emb.}}\approx38.6\text{M}+\underbrace{1024\cdot768}_{\text{positions}}\approx0.8\text{M}\approx\mathbf{124\text{M}}$$

The output layer usually reuses the embedding matrix (weight tying): $\mathbf z_t=\bh_t\bE^\top$, so it adds no parameters. Modern LLMs: the same recipe with $N\approx80$, $d\approx8{,}000$: tens of billions of parameters.

Generating text: one token at a time

Autoregressive: the model gives a distribution over the next token; one token is chosen, appended to the input, and the model runs again.

Training is parallel (the mask), generation is sequential: 500 tokens of answer = 500 forward passes. The KV cache (three slides ahead) makes each pass cheap.

Decoding: from probabilities to text

1.00
8 → –

"Can you please come here?": the history, and the word being predicted.

  • Greedy: always the most likely token. Safe, but repetitive (it loops).
  • Temperature $T$: sample from $\mathrm{softmax}(\bz/T)$, i.e. $p_k\propto e^{z_k/T}$. $T\to0$ is greedy; $T\gt1$ flattens the distribution (more creative, more errors).
  • Top-k / top-p: keep only the $k$ most likely tokens (or the smallest set with probability $p$), renormalize, sample.
  • Beam search: keep the $b$ best partial sentences; used in translation.

The KV cache: do not recompute the past

To choose token $t+1$, the new query $\mathbf q_t$ needs the keys and values of all earlier tokens. The causal mask guarantees that those never change once computed, so we keep them in memory (the KV cache) and only compute the new token's $\mathbf k_t,\mathbf v_t$.

Without it the work for $n$ tokens grows like $1+2+\dots+n=n(n+1)/2$; with it, like $n$. The price is memory: two vectors per layer and per token, for every token of the conversation. It is one of the reasons long contexts are expensive. Lab 14, a 201-token prompt and 200 new tokens: 60,100 token positions processed without the cache, 401 with it, and the same text.

How surprised is the model? Surprisal per token

If the model gave the token that really came the probability $p$, its surprisal is $-\log_2p$ bits: $p=\tfrac12$ costs 1 bit, $p=\tfrac1{1024}$ costs 10. Words that the context makes obvious ("bread" after "a fresh loaf of": 0.3 bits) are almost free; a word that does not fit costs a lot.

These are the real numbers of GPT-2 small from Lab 14. The last word, "elephant", costs 17.3 bits: about 1 chance in 160,000. The average surprisal is the training loss per token (in bits, instead of nats), and $2^{\text{average}}$ is the perplexity: next slide.

Measuring a language model: perplexity

A language model can also score a text: look at the probability it gave to each actual next token. The average of minus their logs is the training loss (cross-entropy per token):

$$J=-\frac1T\sum_{t=1}^{T}\log p(x_t\mid x_{\lt t})$$
$$\text{perplexity}=e^{J}$$

Meaning. If the model gave every true next token probability $\frac14$: $J=\log4$ and the perplexity is 4. The model is as uncertain as if it had to pick among 4 equally likely tokens at every step.

GPT-2 on "Paris is the capital of France.": $J=2.76$ (the slide on scoring a sentence), so the perplexity is $e^{2.76}=15.8$: the fourth row of the table.

Uniform guessing over GPT-2's 50,257 tokens gives perplexity 50,257. Lower is better.

How do companies build bots with custom data?

A chatbot is a language model. It knows what was in its training data, nothing about your documents (price lists, manuals, contracts, last week's news) and, when it does not know, it often makes something up. Three ways to give it your data:

Companies mostly choose the third: Retrieval-Augmented Generation (RAG). Fine-tuning is used to change how a model behaves (tone, format), not to teach it facts.

RAG: the whole pipeline

A · Once. Cut the documents into chunks, turn every chunk into a vector with an embedding model, and store the vectors. A "vector database" is an index over these vectors.

B · For every question. Embed the question with the same model, find the chunks with the most similar vectors, and paste them into the prompt next to the question. The LLM answers from them, and can cite them. It is never retrained.

The next slides open the boxes one by one: embeddings, similarity, search, chunking, search at scale, the prompt, how to measure the retrieval and how to improve it. Lab 15 builds the whole thing.

What is an embedding?

An embedding turns a text (a word, a sentence, a paragraph) into a vector of a few hundred numbers: here 384. The encoder is a transformer: tokens, attention layers, one vector per token, their average (mean pooling), scaled to length 1. Any text, short or long, gives a vector of the same size.

The point: texts with the same meaning get similar vectors, even if they share no words. A single number means nothing; only comparisons do. The question and the Vietnamese-coffee page have cosine 0.70, the gluten-free bakery 0.29. (Lab 15 works in Spanish; the texts are shown translated, the encoder is multilingual.)

Where do embeddings come from?

Training an encoder is chapter 5's word2vec idea for whole sentences. Take millions of pairs of texts that belong together (a question and the text that answers it, two paraphrases, a sentence and its translation). Make their vectors closer, and push away the vectors of texts that do not belong together.

$$\mathcal L=-\log\frac{e^{\cos(\mathbf q,\mathbf d^+)/\tau}}{\sum_je^{\cos(\mathbf q,\mathbf d_j)/\tau}}$$

A softmax over cosines: the right text $\mathbf d^+$ must beat the other texts of the batch ($\tau$ is a temperature). Lab 15 uses a ready-made multilingual encoder trained for paraphrases (118 M parameters, 384 dimensions).

Comparing vectors: dot product, cosine, distance

Three ways to say that two vectors are close:

$$\mathbf a\cdot\mathbf b=\sum_ia_ib_i,\qquad\cos(\mathbf a,\mathbf b)=\frac{\mathbf a\cdot\mathbf b}{\norm{\mathbf a}\,\norm{\mathbf b}},\qquad\norm{\mathbf a-\mathbf b}$$
  • Cosine looks only at the direction: 1 = same, 0 = unrelated, −1 = opposite. The length of the text does not matter.
  • Dot product and distance also depend on the lengths.

From Lab 15: $\mathbf a=(1,2,0)$ and $\mathbf b=10\,\mathbf a$ (the same text repeated 10 times): cosine 1.00 but distance 20.12. $\mathbf c=(2,1,0)$: cosine 0.80 and distance 1.41.

Unit vectors: if every vector has length 1, then $\norm{\mathbf a-\mathbf b}^2=2-2\cos(\mathbf a,\mathbf b)$ and the cosine is just the dot product. All three give the same ranking. That is why embedding models output unit vectors.

Chunking: how to cut the documents

Why cut? The encoder reads a limited number of tokens, one vector cannot summarize ten pages without blurring them, and the prompt is limited and paid by the token. So: pieces of a few hundred tokens (here 40 words, to see them).

Why overlap? A fixed cut can land in the middle of the answer: neither chunk holds it all. Overlap repeats the end of a chunk at the start of the next (more chunks). Small chunks are precise but lose context; large ones keep context but dilute the embedding: tune with the metrics ahead.

Exact search compares the question with all $N$ vectors, $O(N\,d)$: fine for 24 pages, slow for hundreds of millions of chunks.

IVF (inverted file): cluster the vectors once with k-means (the + are the cell centres). For a question, find the nearest centres and scan only the vectors of those cells.

The price: a true neighbour (◯) in a cell you skipped is missed. Lab 15 (200,000 vectors, 512 cells): exact 18.3 ms per question; nprobe = 1: 0.65 ms, 581 vectors, 93 % of the true 10 neighbours; nprobe = 32: 17.3 ms, 98 %, no longer faster.

Dark dots = scanned, grey = skipped. Green ring: the index found that neighbour; red dashed: missed. ◆ = the question. Other indexes (HNSW graphs, product quantization) play the same game.

Measuring retrieval: hit rate@k and MRR

Before judging the LLM's answers, check the search. Take test questions whose relevant chunk is known, and look at the rank of the first relevant chunk in the results (1 = top).

  • Hit rate@k: the fraction of questions whose relevant chunk is in the top $k$ (often called recall@k). If it is not among the $k$ chunks given to the LLM, the LLM cannot use it.
  • Mean reciprocal rank: $\ \mathrm{MRR}=\dfrac{1}{|Q|}\displaystyle\sum_q\frac{1}{\text{rank}_q}$. It is 1 if the answer is always first, 0.5 if always second.

Move $k$: hit@1 $=2/4$, hit@3 $=3/4$ (q2 enters at rank 3), and MRR $=(1+\tfrac13+1+0)/4\approx0.58$ never depends on $k$.

In Lab 15, on 16 questions, the neural encoder gets hit@1 = 0.81 (13 of 16): the questions it misses at rank 1 are "tastings" (rank 2), "waffles with chocolate" (2) and "open in the small hours" (4).

Four ways to embed text: which retrieves best?

Lab 15, 24 pages and 16 questions: the real results of the four embeddings.

  • Word TF-IDF: one dimension per word, rare words weigh more. Fails when the question uses other words: "perro" vs "perros", "bicicleta pinchada" vs "taller de reparación". Similarity is exactly 0 when no word is shared.
  • Character n-grams: pieces of 3–5 letters, so word forms share pieces. A strong baseline here.
  • LSA: 12 dense dimensions from a matrix factorization. 24 short pages give it almost no co-occurrence to learn from.
  • Neural encoder: 384 dense dimensions trained for meaning. On this tiny test set it only ties with character n-grams: our questions share many word pieces with their answers. Its edge should show with paraphrases that share no letters, and across languages. Measure on your own questions: 16 is very few.

Words versus meaning: the similarity matrices

Each row is a question, each column a page; the darker the cell, the more similar. Word TF-IDF (left) is mostly white: most question–page pairs share no word at all, so their similarity is exactly 0. The neural encoder (right) gives a graded similarity to every pair, and the red boxes (the right pages) are usually the darkest cells of their row. Row 15, "my bike has a flat tire": the question says "bicicleta" and the repair shop "bicicletas", two different words for TF-IDF, which ranks that page 22nd; the neural encoder ranks it 1st.

Better retrieval: hybrid search and re-ranking

rank of the right page: keywords – · meaning – · fused –

Hybrid search. Keywords (word TF-IDF here, BM25 in search engines) catch exact names and codes; embeddings catch paraphrases. Reciprocal rank fusion adds $1/(60+\text{rank})$ from each list: it uses only the ranks, so the two scores never need to be comparable. On the 16 Lab 15 questions it fixes 2 and breaks 3 at rank 1 (hit@1 0.81 → 0.75): word TF-IDF is too weak here. Measure before you fuse.

Re-ranking. The sentence encoder embeds the question and each page separately (a bi-encoder): pages are embedded once, so search is fast. A cross-encoder reads question and page together and outputs one relevance score: more accurate, but one forward pass per page. So: retrieve 50 fast, re-rank, keep the best 3–5.

The chapter in one slide

A · Attention

  • each token: $\bq=\bx\bW_Q$, $\bk=\bx\bW_K$, $\bv=\bx\bW_V$
  • $\mathrm{softmax}(\bQ\bK^\top/\sqrt{d_k})\,\bV$: each output is a weighted average of the values
  • $\sqrt{d_k}$ keeps the softmax soft; $h$ heads look for $h$ different things
  • order must be added (positions); the causal mask hides the future

B · The transformer

  • block = attention (communicate) + MLP (think), with residuals and LayerNorm
  • encoder (BERT: both sides) · decoder (GPT: causal) · cross-attention links them
  • one step between any two tokens, parallel training; the price is $n^2$

C · GPT

  • BPE tokens; learn $P(x_t\mid x_{\lt t})$ with cross-entropy
  • $12d^2$ parameters per block: GPT-2 small has 124 M
  • one token at a time: greedy loops, temperature + top-p varies; the KV cache saves work
  • perplexity $=e^{J}$: how many equally likely choices the model hesitates between

D · RAG

  • chunk → embed → store; question → embed → nearest chunks → prompt → answer
  • unit vectors: cosine = dot product, and the same ranking as distance
  • measure the retrieval first: hit rate@k, MRR; then hybrid search, re-ranking
  • retrieved text is data, not instructions

Vocabulary of chapter 6

query, key, value
what a token looks for, what it offers, what it passes on.
attention weights
softmax of $\bq\cdot\bk/\sqrt{d_k}$: one distribution per query.
self / cross-attention
Q, K, V from the same sequence / Q from one, K, V from another.
multi-head
several attentions in parallel, concatenated and mixed by $\bW_O$.
positional encoding
added to the embeddings, since attention ignores order.
causal mask
$-\infty$ above the diagonal: no peeking at the future.
transformer block
attention + MLP, each with a residual and LayerNorm.
BPE token
a sub-word unit from repeated merges of frequent pairs.
temperature, top-k, top-p
how the next token is sampled from the probabilities.
KV cache
keys and values of past tokens kept in memory during generation.
surprisal
$-\log_2p$ bits: how unexpected a token was.
perplexity
$e^{\text{loss}}$: the number of equally likely choices the model hesitates between.
embedding
a text as a vector of numbers; similar meaning, similar vector.
cosine similarity
compares directions; for unit vectors it is the dot product.
chunk, overlap
a piece of a document, and the words repeated between neighbours.
RAG
retrieve relevant chunks by embedding similarity, give them to the LLM.
IVF, nprobe
approximate search: scan only the nearest cells of a clustered index.
hit rate@k, MRR
how often, and how high, the right chunk is retrieved.
hybrid search, RRF
keyword and meaning rankings fused by $1/(60+\text{rank})$.
re-ranker
a cross-encoder that reads question and chunk together.
prompt injection
text in a document that gives orders to the LLM.
