TEST

Finish the three heads

The starting point solves one of the three tasks, the eye positions, with a ResNet-50 and a training loop written by hand. Your job: the other two.

  1. Run the notebook as it is: the data, the ResNet-50 backbone, the eye head, the training loop, the predicted eyes on test faces.
  2. Return the gender and the age from the Dataset, next to the eyes (gender as a float 0/1 for BCEWithLogitsLoss).
  3. Add two heads on the same backbone: gender (1 logit, BCE) and age (1 number, MSE).
  4. Train the three at once with a weighted sum of the losses, and make sure no task dominates (chapter 4: loss scales).
  5. Report each task on the test set next to a trivial baseline: the mean eye position, the majority class, the mean age.

Less boilerplate: PyTorch Lightning

class FaceNet(L.LightningModule):
    def __init__(self):
        super().__init__()
        self.trunk = resnet50(weights="IMAGENET1K_V2")
        self.trunk.fc = nn.Identity()           # 2048 features
        self.eyes = nn.Linear(2048, 4)
        self.gender = nn.Linear(2048, 1)
        self.age = nn.Linear(2048, 1)
        self.mse, self.bce = nn.MSELoss(), nn.BCEWithLogitsLoss()

    def training_step(self, batch, idx):
        h = self.trunk(batch["image"])
        z_eyes = (batch["eyes"] - self.eyes_mu) / self.eyes_sd  # ch. 4
        z_age = (batch["age"] - self.age_mu) / self.age_sd
        loss = (self.mse(self.eyes(h), z_eyes)
              + self.bce(self.gender(h).squeeze(1), batch["gender"])
              + self.mse(self.age(h).squeeze(1), z_age))
        self.log("train/loss", loss)
        return loss                # no backward(), no step()

    def configure_optimizers(self):
        return torch.optim.AdamW(self.parameters(), lr=1e-4)

trainer = L.Trainer(max_epochs=12, gradient_clip_val=1.0,
                    callbacks=[EarlyStopping(monitor="val/loss")])
trainer.fit(FaceNet(), datamodule=dm)       # dm: the data

The training loop of chapter 3 is always the same: zero_grad, backward, step, move data to the GPU, switch train() / eval(), log, save the best checkpoint.

Lightning writes that loop for you. You only fill in the parts that change: the model, training_step (return the loss), validation_step (here the same loss, logged as "val/loss" for early stopping), and configure_optimizers. The sketch standardises the targets with the training-split mean and standard deviation (chapter 4) but leaves out validation_step, those statistics and the data module dm: the solution has them.

The Trainer adds GPU support, gradient clipping, early stopping and checkpointing with one argument each.

It does not make the model better; it removes a family of silent bugs (a forgotten zero_grad, metrics averaged wrongly, eval() never called).
