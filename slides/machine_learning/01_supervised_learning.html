Supervised Learning

Notation:

  • $m$ training samples, $n$ features
  • $x_j^{(i)}$ feature $j$ of sample $i$
  • $\bx^{(i)}$ feature vector $i$ (size $n\times1$)
  • $y^{(i)}$ target $i$
  • $(\bx^{(i)},y^{(i)})$ training pair $i$
  • $\{(\bx^{(i)},y^{(i)})\}_{i=1}^{m}$ training set
  • $\mathcal{X}$ input space, $\mathcal{Y}$ output space
  • $h:\mathcal{X}\to\mathcal{Y}$ hypothesis (the model)

Objective:

  • given a training set
  • learn a function $h$ so that $h(\bx)$ is a "good" predictor of $y$ on new data.
  • $y$ continuous → regression (a price, a cost, a temperature)
  • $y$ discrete → classification (fraud or not, a damage type)

The machine learning workflow

Decide the metric first

What counts as "good"? Euros of error, frauds caught, false alarms… Choose it before training (metrics: chapters 02 and 03).

Always a baseline

The dumbest model: predict the mean (regression) or the most frequent class. Yours must beat it. With 5 % fraud, "never fraud" is already 95 % accurate.

Test once, at the end

Every decision is made with the training and validation data. The test set only gives the final number.

Underfitting and overfitting

20 noisy points from the dashed curve. We fit polynomials of growing degree and measure the error on those 20 points (train) and on 300 new points (test).

  • Underfitting: the model is too simple for the pattern. High error on the training data and on new data.
  • Overfitting: the model is flexible enough to memorize the noise. Low training error, high error on new data.
  • The training error only goes down as the model gets more complex, so it cannot choose the complexity. We need data the model has not seen.

The degree is a hyperparameter: a choice made before training. Parameters $\bth$ are learned on the training set; hyperparameters are chosen on the validation set.

Why a separate test set? After choosing the best of many models on the validation set, its validation score is optimistic: we picked the winner of a contest on that very data. The test set is an independent referee.

If you change the model after looking at the test score, the test set has become a validation set.

What if we only have a small dataset?

K-fold cross validation:

  1. Separate test data.
  2. Split the rest into K folds.
  3. Calculate K metrics:
    • Train on K−1 folds.
    • Validate on the remaining one.
  4. Average the K metrics (and report their spread).
$$\mathrm{CV}=\frac{1}{K}\sum_{k=1}^{K}E_k$$

A frequent choice of K is 5 or 10. Every sample is used for validation exactly once. After choosing the hyperparameters, refit on all the non-test data, then evaluate once on the test set.

Splitting correctly: leakage, classes, groups, time

Data leakage: information from the validation or test data (or from the future) sneaks into training. The scores look great, and the model fails in production.

  • Preprocessing fitted on all the data, e.g. the mean and standard deviation used for scaling. Compute them on the training part only and apply them to the rest. A scikit-learn Pipeline does this automatically, fold by fold.
  • Features known only after the outcome, e.g. "claim paid amount" to predict fraud when the claim is opened.

Classification: stratify the split so every part keeps the class proportions (stratify=y, StratifiedKFold). Essential when a class is rare.

  • Groups: several rows of the same customer, patient or car must all go to the same part (GroupKFold). Otherwise we validate on near-copies of the training data.
  • Time: never shuffle. Train on the past, validate on the future (TimeSeriesSplit). Lab 16 is all about this.
