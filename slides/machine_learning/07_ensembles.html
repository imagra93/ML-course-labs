Ensemble methods: the idea

Class exercise: how much does an Apple AirTag cost? Everyone writes a guess, without talking to anyone.

Each guess is noisy, but the average of the class is usually close to the real price (35 €).

Averaging $B$ independent guesses, each with variance $\sigma^2$, divides the variance by $B$:

$$\mathrm{Var}\Big(\frac1B\sum_{b=1}^Bh_b\Big)=\frac{\sigma^2}{B}$$

If the guesses are correlated (people talk), with correlation $\rho$ between any two:

$$\mathrm{Var}(\bar h)=\rho\,\sigma^2+\frac{1-\rho}{B}\,\sigma^2$$

Ensemble methods: why averaging works (proof)

$B$ models at a fixed point $\bx$. Each has variance $\mathrm{Var}(h_b)=\sigma^2$, and any two have correlation $\rho$, i.e. covariance $\mathrm{Cov}(h_b,h_{b'})=\rho\,\sigma\cdot\sigma=\rho\sigma^2$.

1 · Variance of a sum = all the variances + the covariances of all pairs:

$$\mathrm{Var}\Big(\sum_{b=1}^Bh_b\Big)=\sum_b\mathrm{Var}(h_b)+\sum_{b\ne b'}\mathrm{Cov}(h_b,h_{b'})$$

2 · Count the terms, in plain words. Squaring a sum multiplies every term by every term: $(a+b+c)(a+b+c)$ gives $3\times3=9$ products. Three are a term with itself ($a^2,b^2,c^2$), six are two different terms ($ab,ba,ac,ca,bc,cb$). The variance of a sum works the same way, with covariances. $$=B\sigma^2+B(B-1)\,\rho\sigma^2$$

3 · The average is the sum times $\frac1B$, and $\mathrm{Var}(cX)=c^2\,\mathrm{Var}(X)$:

$$\mathrm{Var}(\bar h)=\frac{B\sigma^2+B(B-1)\rho\sigma^2}{B^2}=\frac{\sigma^2}{B}+\frac{B-1}{B}\,\rho\sigma^2$$

4 · Rearrange, using $\frac{B-1}{B}=1-\frac1B$:

$$=\frac{\sigma^2}{B}+\rho\sigma^2-\frac{\rho\sigma^2}{B}=\rho\sigma^2+\frac{1-\rho}{B}\,\sigma^2\quad\blacksquare$$

Numbers: $\sigma^2=1$, $\rho=0.3$. One model: 1.  $B=10$: $0.3+0.07=0.37$.  $B=100$: $0.307$.  $B\to\infty$: $0.3$.

  • Averaging does not change the bias (the average of the models has the same expected value as one model), so average low-bias models: deep trees.
  • As $B\to\infty$ the second term vanishes: more trees never overfit, the error just levels off.
  • The floor $\rho\sigma^2$ only goes down if the models are less alike.

We have one training set of $m$ examples. To get "different" ones, draw $m$ examples with replacement: a bootstrap sample. How likely is an example to be left out? Follow example #1.

One draw. We pick one of the $m$ examples at random. It is #1 with probability $\frac1m$, so it is not #1 with probability $1-\frac1m$. With $m=10$: $1-\frac1{10}=\frac9{10}$.

All the draws. The example goes back after each draw, so the $m$ draws are independent, each with the same chance of missing #1. To be left out, #1 must be missed every time: multiply the $m$ chances.

$$P(\text{left out})=\underbrace{\Big(1-\frac1m\Big)\cdots\Big(1-\frac1m\Big)}_{m\text{ factors}}=\Big(1-\frac1m\Big)^m$$

$m=10$: $0.9\times0.9\times\dots$ (ten times) $=0.9^{10}=0.349$, about 35 %.

Each column adds up to 6: every tree is trained on 6 draws.

For every training example:

  1. take only the trees that did not see it (its OOB trees),
  2. average their predictions for it (example 4: trees 3 and 4),
  3. compare with its true label.

The average error over all examples is the OOB error. Every prediction is made by trees that did not train on that example, so it estimates the test error, like cross-validation, but for free: no extra training and no held-out set.

With many trees, each example is OOB for about 37 % of them. In scikit-learn: RandomForestClassifier(oob_score=True), then read oob_score_.

Ensemble methods: bagging

Bootstrap aggregating (Breiman, 1996):

for b = 1, ..., B:
    draw a bootstrap sample D_b (m examples)
    fit a deep tree h_b on D_b     # no pruning
predict:
    regression:      average of the h_b(x)
    classification:  majority vote
                     (or average the probabilities)

It helps any unstable model (small changes in the data → big changes in the model): deep trees are the classic case. A stable model such as linear regression gains almost nothing.

Ensemble methods: random forest

Random forest (Breiman, 2001) = bagging + one more source of randomness:

  1. Draw $B$ bootstrap samples of the training set.
  2. On each one grow a deep tree, but at every split only a random subset of max_features features may be used (a new subset at each node).
  3. Combine the $B$ trees: majority vote or average of the probabilities (classification), average (regression).

Why the random features? Bagged trees are still correlated: if one feature is very strong, almost every tree puts it at the top, the trees look alike, and $\rho$ stays high.

Random features make the trees less alike: lower $\rho$, lower floor $\rho\sigma^2$. Each tree gets a little worse, but the average gets better.

Typical max_features, with $n$ features: $\sqrt n$ for classification, $n/3$ for regression (scikit-learn's default there is all $n$). Using all $n$ features is plain bagging.

Random forest: review

Pros

  • Much less overfitting than a single tree; very good accuracy with little tuning.
  • No feature scaling; handles non-linear effects and interactions.
  • Robust to outliers in the inputs (trees only use the order of the values).
  • Trees are independent: training runs in parallel. The OOB error comes for free.

Cons

  • Less interpretable than one tree; bigger and slower to predict ($B$ trees).
  • Can't extrapolate beyond the training range.
  • Less suited to very sparse, high-dimensional data (e.g. text), where linear models do well.
HyperparameterEffect

Feature importance. MDI (feature_importances_): add up the impurity decreases of all the splits on each feature, averaged over the trees. Free, but computed on training data and biased towards features with many distinct values.

Permutation importance: shuffle one feature in the validation data and measure how much the score drops. More trustworthy.

Boosting: the idea

Bagging: many strong (deep) models trained independently, in parallel. The average lowers the variance.

Boosting: many weak models (shallow trees) trained one after another. Each one focuses on what the ensemble so far gets wrong. It lowers the bias.

The result is an additive model: a weighted sum of $M$ weak learners,

$$F_M(\bx)=\sum_{t=1}^M\alpha_t\,h_t(\bx)$$

Two ways to "focus on the mistakes": AdaBoost re-weights the training examples; gradient boosting fits each new tree to the remaining errors (the residuals).

AdaBoost: the algorithm, in words

AdaBoost combines stumps: trees with a single question. Every training point carries a weight, how much it matters. At the start all weights are equal.

Round after round:

  1. Train a stump on the weighted data. Heavy points are the ones it must get right.
  2. Count its mistakes: add up the weights of the points it got wrong. This is its weighted error.
  3. Give it a vote. The fewer its mistakes, the bigger its say. A stump no better than a coin flip gets no say at all.
  4. Re-weight the points. The ones it got wrong become heavier, the ones it got right lighter. The next stump is forced to look at the hard cases.

Final answer: all the stumps vote, and a stump's vote counts as much as its say: the best stumps decide.

Round 1 of the next demo. 30 points, each with weight $\frac1{30}$. The best stump gets 5 of them wrong.

Its error is 5 out of 30, about 17 %: much better than a coin flip (50 %), so it earns a good say. In the demo this number is the weighted error $\varepsilon$ and its say is the vote $\alpha=0.80$ (a coin flip would get 0).

Gradient boosting: fit the residuals

Regression. Instead of re-weighting points, each new tree learns what is still missing: the error the current model still makes on every example.

  1. Start with a boring prediction: the average of all the targets, the same for everybody.
  2. For each example, compute the residual: real value minus current prediction. Positive: we predict too low. Negative: too high.
  3. Train a small tree to predict those residuals from the features.
  4. Add a fraction of the tree's answer to the current prediction (the fraction is the learning rate $\nu$, here $\frac12$). Go back to 2.

Why only a fraction? Many small corrections generalize better than a few big ones.

By hand: 4 points, stumps, learning rate $\frac12$. The start is the average $\frac{2+4+8+10}{4}=6$.

Gradient boosting: why "gradient"?

Remember gradient descent: to lower a loss, nudge what you can change a little in the direction where the loss goes down fastest.

Boosting does the same, but what it nudges is not a weight: it is the prediction for every training example. The loss says, for each example, in which direction its prediction should move.

Squared error: that direction is simply real value − prediction, the residual. So fitting the residuals is a gradient-descent step.

Why a tree? Nudging predictions directly only works on the training examples. A small tree learns the pattern of the nudges from the features, so the step also works for a new $\bx$. It is gradient descent on functions instead of on numbers.

Any loss works. Use the direction in which that loss goes down (the pseudo-residual) and fit the tree to it. Same recipe, another loss.

Classification (log-loss): the direction is real label (0 or 1) − predicted probability. The same "prediction minus target" as in logistic regression, with the sign flipped.

real labelpredicted probabilitydirection
10.8+0.2: push up a little
00.8−0.8: push down hard

A confident mistake gets a big push, a good prediction a small one.

The starting guess is the best constant: the average of the targets (squared error) or the overall rate of positives (classification).

XGBoost

eXtreme Gradient Boosting: gradient boosting with penalties on complex trees and a very fast implementation.

  • $\lambda$ (reg_lambda) shrinks the leaf values (right). $\gamma$ (gamma) is the minimum improvement a split must bring, or it is not made.
  • It looks at the slope of the loss and at how curved it is (first and second derivatives): a smarter step, called a Newton step.
  • Learning rate eta, row and column subsampling, early stopping, missing values, parallel split search.
  • A top choice for tabular data, with LightGBM and CatBoost. For images, audio and text, deep learning wins.

The value of a leaf (squared loss). In plain gradient boosting a leaf answers the average residual of the examples that fall in it.

XGBoost penalizes big leaf values. The effect is easy to picture: as if $\lambda$ extra examples with residual 0 had fallen in the leaf, and then we take the average:

$$\text{leaf value}=\frac{\text{sum of the residuals}}{\text{number of examples}+\lambda}$$

$\lambda=0$: the plain average. $\lambda\gt0$: pulled towards 0, much more for a leaf with few examples (little evidence) than for a big one.

Example: residuals $\{2,4\}$ and $\lambda=1$: $\frac{6}{2+1}=2$ instead of 3. A leaf with 100 examples is barely touched: $\frac{100}{101}\approx0.99$ of its average.
