Attention and the transformer architecture

imanolgranada@gmail.com

Problems with LSTMs:

  • Inputs are sequential: no parallelization. Step $t$ must wait for step $t-1$.
  • No explicit modelling of long- and short-range dependencies.
  • The distance between positions matters: information from far away must survive many steps.
  • The whole input is squeezed into one fixed-size state.

What we want:

  • handle inputs of different lengths,
  • parallel processing of the entire input,
  • shared parameters (like CNNs),
  • any position reachable from any other in one step.

Attention Is All You Need

Vaswani, Shazeer, Parmar, Uszkoreit, Jones, Gomez, Kaiser, Polosukhin · 2017

The paper that introduced the transformer: no recurrence, no convolution, only attention. Behind GPT, BERT, translation, speech (Whisper) and vision (ViT).

Why attention: the bottleneck

Before attention, sequence models compressed an entire input sequence into a single fixed-size vector before decoding it. Long sequences lost information by the time they reached the output.

Attention (Bahdanau 2014) fixes this by letting the decoder look back at every input position every time it produces an output, and decide how much each one matters.

Attention in translation: a soft alignment

When writing each Spanish word, the decoder computes a weight for every English word, then reads a weighted average of their encoder states.

$$\bc_t=\sum_j\alpha_{tj}\,\bh_j,\qquad\sum_j\alpha_{tj}=1$$

Nobody tells the network that "negro" goes with "black". The weights are learned end to end, only from pairs of sentences.

The transformer takes this idea to its limit: attention everywhere, and no recurrence at all.

Attention mechanism: a soft dictionary lookup

A Python dictionary returns the value whose key exactly matches the query. Attention returns a weighted mix of all the values, weighted by how well each key matches:

  • Query $\bq$: what am I looking for?
  • Keys $\bk_j$: what does each position offer?
  • Values $\mathbf v_j$: what does each position pass on?
$$\alpha_j=\mathrm{softmax}_j\big(\bq^\top\bk_j\big),\qquad\text{output}=\sum_j\alpha_j\,\mathbf v_j$$
d = {"cat": v1, "dog": v2, "car": v3}
d["cat"]          # hard lookup → v1

# attention, query ≈ "kitten":
# weights  cat 0.80, dog 0.18, car 0.02
# output = 0.80·v1 + 0.18·v2 + 0.02·v3

The weights are positive and sum to 1: the output is a linear combination of the values.

Everything is differentiable, so the queries, keys and values can be learned by backprop.

Attention with numbers

Three tokens with 2-dimensional keys and values. We compute the new vector for "pizza", whose query is $\bq=(2,1)$:

$$\text{scores}=\tfrac{1}{\sqrt2}\big(\bq\cdot\bk_{\text I},\ \bq\cdot\bk_{\text{love}},\ \bq\cdot\bk_{\text{pizza}}\big)=\tfrac1{\sqrt2}(2,1,3)$$
$$\boldsymbol\alpha=\mathrm{softmax}(1.41,\,0.71,\,2.12)=(0.28,\,0.14,\,0.58)$$
$$\text{out}=0.28\binom10+0.14\binom01+0.58\binom{0.5}{0.5}=\binom{0.57}{0.43}$$

Every token does this at the same time, each with its own query.

Self-attention:

A sequence of $n$ tokens $\{\bx_1,\dots,\bx_n\}$, each a vector of size $d_{\text{model}}$. For each token we create three vectors with learned matrices:

$$\bq_i=\bx_i\bW_Q,\qquad\bk_i=\bx_i\bW_K,\qquad\mathbf v_i=\bx_i\bW_V$$

$\bW_Q,\bW_K\in\R^{d_{\text{model}}\times d_k}$, $\bW_V\in\R^{d_{\text{model}}\times d_v}$ (typically $d_k=d_v=d_{\text{model}}/h$). "Self": queries, keys and values all come from the same sequence.

How much token $i$ should focus on token $j$:

$$\text{score}(i,j)=\frac{\bq_i\cdot\bk_j}{\sqrt{d_k}},\qquad\alpha_{ij}=\frac{\exp(\text{score}(i,j))}{\sum_{k=1}^n\exp(\text{score}(i,k))}$$
$$\mathrm{Attention}(\bx_i)=\sum_{j=1}^n\alpha_{ij}\,\mathbf v_j$$

All tokens at once, in matrix form ($\bQ=\bX\bW_Q$, $\bK=\bX\bW_K$, $\bV=\bX\bW_V$):

$$\mathrm{Attention}(\bQ,\bK,\bV)=\mathrm{softmax}\Big(\frac{\bQ\bK^\top}{\sqrt{d_k}}\Big)\bV$$

$\bQ\bK^\top$ is $n\times n$: every token against every token. The softmax is taken row by row. Each token ends up as a combination of all the tokens in the sequence, weighted by the attention scores.

Why separate Q and K? "What I look for" and "what I offer" are different: a verb looks for its subject, a noun offers itself as one. Two matrices let the relation be asymmetric.

Self-attention as matrices

Example: $n=10$ tokens, $d=512$, $d_k=64$. $\bQ,\bK,\bV$ are $10\times64$, the score matrix is $10\times10$, the output is again one vector per token.

Cost: $O(n^2d)$. Doubling the context quadruples the attention cost: why context windows are limited and why long-context tricks exist (FlashAttention, sparse attention).

Why divide by $\sqrt{d_k}$?

Suppose the components of $\bq$ and $\bk$ are independent with mean 0 and variance 1:

$$\E[\bq^\top\bk]=\sum_{i=1}^{d_k}\E[q_i]\,\E[k_i]=0$$
$$\mathrm{Var}(\bq^\top\bk)=\sum_{i=1}^{d_k}\mathrm{Var}(q_ik_i)=\sum_{i=1}^{d_k}\E[q_i^2]\,\E[k_i^2]=d_k$$

Raw dot products have standard deviation $\sqrt{d_k}$ (8 for $d_k=64$). Large scores push the softmax into saturation: nearly one-hot, where its gradient is nearly 0.

Dividing by $\sqrt{d_k}$ brings the variance back to 1, whatever the dimension. $\blacksquare$

Self-Attention and multihead:

Train several attentions in parallel and let each focus on different things (syntax, coreference, position…).

$$\mathrm{head}_i=\mathrm{Attention}\big(\bX\bW_Q^{(i)},\bX\bW_K^{(i)},\bX\bW_V^{(i)}\big)$$
$$\mathrm{MultiHead}(\bX)=\mathrm{Concat}(\mathrm{head}_1,\dots,\mathrm{head}_h)\,\bW_O$$

With $h$ heads of size $d_k=d/h$, the cost is about the same as one big head. Example: $d=768$, $h=12$, $d_k=64$.

Different heads, different jobs

One head alone gives one weighted average per token: it cannot look at the previous word and at the subject at the same time. With several heads, each builds its own pattern, and $\bW_O$ mixes their results. Researchers find heads like these (previous-token, coreference, "induction" heads that copy patterns) in trained language models.

Positional encodings:

Does the order of words matter? Permute the input rows: $\bQ\bK^\top$ and the output are permuted the same way. Self-attention is permutation-equivariant: "dog bites man" = "man bites dog".

So we add an encoding of the position to each embedded input:

$$\text{input}_t=\text{embedding}(\text{token}_t)+PE(t)$$
$$PE_{(pos,2i)}=\sin\Big(\frac{pos}{10000^{2i/d}}\Big),\qquad PE_{(pos,2i+1)}=\cos\Big(\frac{pos}{10000^{2i/d}}\Big)$$

Each pair of dimensions is a clock at a different speed. Relative positions become easy to read: $PE(pos+k)$ is a fixed rotation of $PE(pos)$. GPT-2 instead learns a position embedding; modern LLMs rotate $\bq,\bk$ directly (RoPE).

Self-Attention mask:

The mask is optional, but it is used where it does not make sense for a word to look at future words, because they are not available in reality: not for classifying a known sentence, but for next-word prediction.

$$\mathrm{softmax}\Big(\frac{\bQ\bK^\top}{\sqrt{d_k}}+\mathbf M\Big)\bV,\qquad M_{ij}=\begin{cases}0&j\le i\\-\infty&j\gt i\end{cases}$$

$e^{-\infty}=0$: future tokens get exactly zero weight. And one forward pass trains all $n$ next-token predictions of a sequence at once.

Transformer encoder-decoder:

Each block (pre-norm version):

$$\bX\leftarrow\bX+\mathrm{MHA}\big(\mathrm{LN}(\bX)\big)$$$$\bX\leftarrow\bX+\mathrm{MLP}\big(\mathrm{LN}(\bX)\big)$$
  • Attention mixes information between positions; the MLP ($d\to4d\to d$, GELU) processes each position separately: "communicate, then think".
  • Residual connections and LayerNorm make deep stacks trainable (chapters 3–4).
  • Cross-attention: queries from the decoder, keys and values from the encoder: the alignment of translation.

Language modelling: the objective behind GPT

By the chain rule of probability, any sequence factorizes as

$$P(x_1,\dots,x_T)=\prod_{t=1}^TP(x_t\mid x_1,\dots,x_{t-1})$$

So it is enough to learn one thing: the next token given the previous ones. A $|V|$-class classification with softmax and cross-entropy, exactly chapter 1.

Text is first split into sub-word tokens by byte-pair encoding: start with characters, repeatedly merge the most frequent adjacent pair. Frequent words become one token, rare ones are split, nothing is ever unknown.

GPT: counting the parameters

Token + position embedding → $N$ identical blocks → final LayerNorm → linear layer to $|V|$ logits. Per block, ignoring biases and LayerNorms:

  • Attention: $\bW_Q,\bW_K,\bW_V,\bW_O$, each $d\times d$: $\ 4d^2$.
  • MLP with hidden size $4d$: $\ d\cdot4d+4d\cdot d=8d^2$.
  • Total: $12d^2$ per block.

GPT-2 small: $N=12$, $d=768$, $|V|=50{,}257$, 1,024 positions:

$$\underbrace{12\cdot12\cdot768^2}_{\text{blocks}}\approx84.9\text{M}+\underbrace{50{,}257\cdot768}_{\text{token emb.}}\approx38.6\text{M}+\underbrace{1024\cdot768}_{\text{positions}}\approx0.8\text{M}\approx\mathbf{124\text{M}}$$

The output layer usually reuses the embedding matrix (weight tying): $\mathbf z_t=\bh_t\bE^\top$. Modern LLMs: the same recipe with $N\approx80$, $d\approx8{,}000$: tens of billions of parameters.

Generating text: one token at a time

Autoregressive: the model gives a distribution over the next token; one token is chosen, appended to the input, and the model runs again.

Training is parallel (the mask), generation is sequential: 500 tokens of answer = 500 forward passes. The keys and values of past tokens are cached so each pass only processes the new token.

"Can you please come here?": the history, and the word being predicted.

  • Greedy: always the most likely token. Safe, but repetitive (it loops).
  • Temperature $T$: sample from $\mathrm{softmax}(\mathbf z/T)$. $T\to0$ is greedy; $T\gt1$ flattens the distribution (more creative, more errors).
  • Top-k / top-p: keep only the $k$ most likely tokens (or the smallest set with probability $p$), renormalize, sample.
  • Beam search: keep the $b$ best partial sentences; used in translation.

How do companies build bots with custom data?

Retrieval-Augmented Generation (RAG): the LLM is not retrained. Instead, the most relevant pieces of your documents are found by embedding similarity and pasted into the prompt, so the model answers from them.

The embeddings come from an encoder transformer trained so that texts with similar meaning get similar vectors: chapter 5's word2vec idea, for whole paragraphs.

Chunking, embeddings and chunk selection:

  • Split each document into chunks (a few hundred tokens, with some overlap).
  • Turn each chunk into an embedding vector: dim 512, 768, 1,024…
  • Cosine similarity to select the top-$k$ chunks for a question:
$$\cos(\mathbf a,\mathbf b)=\frac{\mathbf a\cdot\mathbf b}{\norm{\mathbf a}\,\norm{\mathbf b}}$$

Evaluate retrieval with recall@k and MRR, before judging the generated answers.
