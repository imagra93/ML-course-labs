Part A
Convolutions

An image is a grid of numbers

Neural networks are not restricted to vectors of features. They also accept formatted data:

  • 1D: audio, temporal signals.
  • 2D: black and white images.
  • 3D: coloured pictures (channels × height × width).
  • 4D: coloured video.

Mini-batches add an extra dimension 0: [batch, channels, H, W]. For a single image at prediction time, reshape it to a batch of 1: x.unsqueeze(0).

Why not flatten the image into an MLP?

  • Too many parameters. A 224×224 RGB image is 150,528 numbers. One dense layer of 1,000 units: 150 million weights.
  • No notion of position. A cat in the top-left and the same cat in the bottom-right share nothing: the MLP must learn the pattern at every position separately.
  • No notion of neighbourhood. Neighbouring pixels are related, far ones much less: after flattening, pixel (0,0) is as "close" to (0,1) as to (223,223).

Two ideas fix all three problems:

  1. Local connections: each unit looks at a small patch (3×3), not at the whole image.
  2. Weight sharing: the same small set of weights is used at every position.

Together they give the convolutional layer. A 3×3 conv from 3 to 64 channels has 1,792 parameters, whatever the image size.

Convolutional layers - CNN:

1 / 9
  • The same filter (small, few parameters) is applied throughout the image.
    • Parameter 1 → kernel size ((3,3) in the example).
    • Parameter 2 → stride, the "jump" between calculations ((1,1) here).
    • Parameter 3 → padding (add zeros in the border).
  • The stride and the padding determine the size of the output matrix.
  • A filter "learns" certain features of the input: an edge, a corner, a texture.
$$Z_{ij}=\sum_{u=0}^{F-1}\sum_{v=0}^{F-1}X_{i+u,\,j+v}\,K_{uv}+b$$

Strictly this is cross-correlation (no kernel flip). Since the kernel is learned, nobody cares.

A filter is a pattern detector

The output of a convolution is a feature map: large where the image locally looks like the kernel, near zero elsewhere. A dot product is a similarity score.

Hand-made kernels like these (Sobel) were the classic computer-vision features. A CNN learns its kernels by backprop: the 9 numbers are parameters like any other weight.

Why? With padding the input is $H+2P$ wide. The first window starts at 0 and the last must start at most at $H+2P-F$. Starting points every $S$ steps: $\lfloor(H+2P-F)/S\rfloor+1$ of them.

  • "same" padding: $P=(F-1)/2$ with $S=1$ keeps $H_{\text{out}}=H$.
  • Stride 2 halves the size: down-sampling.
  • Example: $H=224,F=7,P=3,S=2$ → $\lfloor 223/2\rfloor+1=112$ (ResNet's first layer).

Convolutional layers - many filters

$$\#\text{params}=(F\cdot F\cdot C_{\text{in}}+1)\cdot C_{\text{out}}$$

3×3 conv, 64 → 128 channels: $(9\cdot64+1)\cdot128=73{,}856$ parameters, whatever the image size.

  • The input has $C_{\text{in}}$ channels (3 for RGB). Each filter is $F\times F\times C_{\text{in}}$: the third dimension matches the previous layer's automatically.
  • $C_{\text{out}}$ filters → an output with $C_{\text{out}}$ channels ("feature maps").
  • PyTorch: nn.Conv2d(in_channels=3, out_channels=64, kernel_size=3, stride=1, padding=1).

Weight sharing ⇒ translation equivariance. Shift the input by $(a,b)$, $X'_{ij}=X_{i-a,j-b}$:

$$Z'_{ij}=\sum_{u,v}X_{i-a+u,\,j-b+v}K_{uv}=Z_{i-a,\,j-b}$$

The output shifts by the same amount: a pattern is detected wherever it appears. Pooling then adds a little invariance to small shifts. $\blacksquare$

Pooling layers - CNN:

Down-sampling can be done with the stride: stride (2,2) divides the size by 2 at every conv layer.

A more robust and common approach is a pooling layer (after the non-linear activation).

The pooled feature map is a summarized version of the features detected in the input. Max pooling asks "is the pattern present somewhere in this region?", which tends to be more informative than its average presence.

  • No parameters.
  • Halves height and width: 4× less computation for the next layer.
  • Backward: the gradient goes only to the max (the "router" gate of chapter 2).

Receptive field: how much of the image does a unit see?

2
receptive field–

Each 3×3 layer adds 2 pixels. A stride or a pooling multiplies how much every following layer adds:

$$r_l=r_{l-1}+(F_l-1)\prod_{i\lt l}S_i$$

Lab CNN (conv3 → pool2 → conv3 → pool2): 3, 4, 8, 10 pixels. ResNet-50: several hundred: the last layer sees the whole image.

Stacking: layers close to the input learn low-level features (edges); deeper layers combine them into shapes and objects, because they see a larger patch.

Part B
Architectures and transfer learning

Basic CNN architecture:

model = nn.Sequential(
  nn.Conv2d(1, 32, 3, padding=1), nn.ReLU(), # 28×28×32
  nn.MaxPool2d(2),                            # 14×14×32
  nn.Conv2d(32, 64, 3, padding=1), nn.ReLU(), # 14×14×64
  nn.MaxPool2d(2),                            # 7×7×64
  nn.Flatten(),                               # 3136
  nn.Linear(3136, 128), nn.ReLU(),
  nn.Linear(128, 10))                         # logits

Pooling combined with more filters! The spatial size shrinks while the number of channels grows. Then flatten and classify with dense layers.

95 % of the weights sit in the first dense layer: that is why modern nets use global average pooling instead.

Famous architectures: AlexNet, VGG, ResNet

AlexNet (2012)

First big CNN on GPUs, with ReLU and dropout. Won ImageNet by a huge margin (16 % vs 26 % error). 60 M parameters.

VGG (2014)

Only 3×3 convs and 2×2 max-pools. Two 3×3 layers see a 5×5 patch with 18 weights instead of 25, plus an extra non-linearity. VGG16, VGG19.

ResNet (2015)

A 56-layer plain CNN did worse than a 20-layer one, in training too: not overfitting, but optimization. Skip connections fixed it: 152 layers.

Residual connections

Instead of learning $H(\bx)$ directly, learn a correction $F(\bx)$ and add the input back:

$$\bh=F(\bx)+\bx\quad\Rightarrow\quad\frac{\partial\bh}{\partial\bx}=\frac{\partial F}{\partial\bx}+\bI$$
  • The Jacobian always contains the identity: the gradient reaches early layers even if $F$'s gradient is tiny (the "add gate" copies it).
  • If a block is not useful, it can learn $F\approx0$ and become the identity: a deeper net is at least as good as a shallower one.
  • The same trick is in every transformer block (chapter 6).

Inception modules instead run 1×1, 3×3 and 5×5 convolutions in parallel and concatenate them, for features of different sizes.

Two useful tricks: 1×1 convolutions and global pooling

1×1 conv: a dense layer applied at every pixel, across channels. Used to shrink 256 channels to 64 before an expensive 3×3 conv (the "bottleneck" of ResNet-50), and as the classifier of segmentation heads.

Global average pooling: average each feature map to one number. A 7×7×512 tensor becomes 512 numbers, then one Linear(512, K). Few parameters, and the network accepts any image size.

Looking inside a CNN

The first layer of any CNN trained on photos learns oriented edges and colour blobs, much like the early visual cortex. That is why those layers transfer so well to new tasks.

Grad-CAM: take the gradient of a class score with respect to the last feature maps, weight the maps, and overlay them on the image. If a "wolf" classifier lights up on the snow, it learned a shortcut.

Transfer learning:

You can use the same neural net as Google, but you do not have the same amount of data!

The first conv layers learn to extract general features from images (edges, textures), so you can reuse that knowledge in new problems:

  • Download a trained net (with the learned weights).
  • Fix (freeze) the first layers, where the complex feature engineering happens.
  • Replace or randomly initialize the last fully connected layers: they learn the more specific, "high-level" features of your problem.
  • Train these (fewer) weights with your (smaller) dataset, with a small learning rate.
m = torchvision.models.resnet18(weights="DEFAULT")
for p in m.parameters(): p.requires_grad = False
m.fc = nn.Linear(m.fc.in_features, n_classes)  # new head

Data augmentation:

  • Flip, rotation, crop: the object can appear anywhere, at any small angle.
  • Colour shift, noise: tolerance to lighting, camera quality.
  • Cut-out (information loss): parts of the object can be hidden.

Only transformations that keep the label! Applied on the fly, a new random version each epoch. For detection and segmentation, the boxes and masks must be transformed too.

Semantic segmentation = classify every pixel

car

Classification: one softmax per image. Segmentation: one softmax per pixel. Same loss, just averaged over $H\times W$ positions:

$$J=-\frac{1}{HW}\sum_{i,j}\log\hat p_{i,j}\big(y_{i,j}\big)$$

The labels are masks: an integer image with the class of every pixel (painted by hand, expensive!).

PyTorch: nn.CrossEntropyLoss() accepts logits $[B,K,H,W]$ and targets $[B,H,W]$ directly.

Problem: the backbone shrinks the image 32×. We need a way to go back up to full resolution.

Fully convolutional networks

Classification head: pool everything into one vector, lose the "where". Segmentation head: keep the spatial grid, predict $K$ scores at each cell with a 1×1 conv, then upsample to the input size.

Upsampling ×32 in one go gives blobby masks. Better: go up gradually, and reuse the high-resolution features of the early layers. That is the U-Net.

Going up: nearest, bilinear, transposed convolution

  • Nearest / bilinear: fixed rules, no parameters. Usually followed by a normal conv to refine (nn.Upsample).
  • Transposed convolution: each input value "paints" a copy of a learned kernel, scaled by the value, onto the output; overlaps add up (nn.ConvTranspose2d).

Same parameters as a conv: kernel size, stride, padding. With stride 2 it doubles $H$ and $W$: exactly the mirror of a stride-2 conv, and its backward pass is a normal convolution.

U-Net: encoder, decoder, skip connections

  • Encoder (left, down): conv + pooling, like any CNN, often a pre-trained ResNet. Understands what is in the image.
  • Decoder (right, up): upsampling + conv. Recovers where.
  • Skip connections (dashed): copy the encoder's feature maps at each resolution and concatenate them to the decoder's. They bring back the fine detail (exact borders) that the bottleneck lost.

Output: $K$ channels at full resolution, one per class. Born in medical imaging (2015), still the default for segmentation, and the core of image generators like Stable Diffusion.

Measuring masks: IoU and Dice

1
2.6
IoU–
Dice–
$$\mathrm{IoU}=\frac{|P\cap G|}{|P\cup G|},\qquad\mathrm{Dice}=\frac{2|P\cap G|}{|P|+|G|}$$

Why not pixel accuracy? If damage covers 2 % of the image, predicting "no damage" everywhere is 98 % accurate and useless. IoU ignores the easy background.

mIoU: the IoU of each class, averaged. The standard segmentation metric.

Dice loss $=1-\mathrm{Dice}$ computed on the soft probabilities, often added to the cross-entropy to fight class imbalance.

Object detection: what and where

  • Classification: what is in the image?
  • Localization: what, and where? One box $(x,y,w,h)$ regressed by the network, plus the class: a loss that combines regression and classification.
  • Detection: all the objects, a box, a class and a confidence for each. Unknown number of objects!

Most bugs in detection code are box-format bugs: always check which convention a library and a dataset use.

Three generations of detectors

Two-stage detectors are more accurate on small objects; one-stage ones are fast enough for video. Modern YOLO versions closed most of the accuracy gap, which is why they are the practical default. Transformers also detect: DETR predicts a set of boxes directly.

YOLO: every grid cell predicts

–

The backbone turns the image into an $S\times S$ grid of feature vectors. A 1×1 conv head predicts, for every cell at once:

  • an objectness score: is there an object whose centre is here?
  • the box: centre offset inside the cell, width, height;
  • class probabilities.

One forward pass = all boxes. That is "You Only Look Once", and why it runs in real time.

Real YOLOs use 3 grids of different sizes (small, medium, large objects), and each cell can predict more than one box.

Training a detector: the loss

For each cell (or anchor) that is assigned a true object:

$$J=\lambda_{\text{box}}\,\underbrace{J_{\text{box}}}_{\text{1 − IoU, L1}}+\lambda_{\text{obj}}\,\underbrace{J_{\text{obj}}}_{\text{BCE}}+\lambda_{\text{cls}}\,\underbrace{J_{\text{cls}}}_{\text{BCE / CE}}$$
  • Box: regression of 4 numbers. Losses based on IoU (GIoU, CIoU) don't depend on the object's size.
  • Objectness: binary classification, for every cell (most say "no object").
  • Class: only for the cells that have an object.

Assignment decides which predictions are responsible for which true object: the cell containing the centre (YOLOv1), the anchor boxes with the best IoU (YOLOv3–5), or a learned score of IoU and class quality (YOLOv8–11, "task-aligned").

It is the same recipe as the multi-task face lab: one backbone, several heads, a weighted sum of losses.

Class imbalance is huge (thousands of background cells for a few objects): focal loss and careful weighting exist for that.

IoU for boxes: when is a prediction correct?

1.0
1.0
IoU–
at threshold 0.5–
$$\mathrm{IoU}(B_p,B_g)=\frac{\text{area}(B_p\cap B_g)}{\text{area}(B_p\cup B_g)}$$

A prediction matches a true object if the class is right and their IoU is at least a threshold (often 0.5). Matched: true positive. Unmatched prediction: false positive. Unmatched truth: false negative.

IoU 0.5 is stricter than it sounds: shifting a square by a third of its side already gets you there.

Non-maximum suppression, step by step

Neighbouring cells all see the same object, so the raw output has many near-duplicate boxes. Post-processing:

  1. Drop boxes below a confidence threshold (e.g. 0.25).
  2. Sort the rest by score.
  3. Keep the best; remove every other box of the same class with IoU above ~0.5 with it.
  4. Repeat with the next remaining box.
keep = torchvision.ops.nms(boxes, scores, iou_threshold=0.5)

Two people hugging can be wrongly merged: the IoU threshold is a trade-off.

Evaluating detectors: precision, recall, mAP

  • Sort all predictions of a class by score. Walk down the list: each one is a TP or an FP.
  • Running precision = TP / predictions so far; recall = TP / true objects.
  • AP: area under the precision–recall curve (made monotone first).
  • mAP: the mean of AP over classes. mAP@0.5 uses IoU ≥ 0.5; mAP@0.5:0.95 (COCO) averages over 10 thresholds, rewarding precise boxes.

Same precision and recall as in the logistic-regression classes: AP is the detection version of the area under a curve.
