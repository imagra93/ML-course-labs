Non-vectorial inputs to NN:

Neural networks are not restricted to inputs in the form of a vector of features. They also accept formatted data, for example:

  • 1D vectors containing temporal data.
  • 2D matrices containing (black and white) images.
  • 3D arrays containing coloured pictures.
  • 4D arrays containing coloured video.

Since networks are trained with mini-batch gradient descent, we add an extra dimension (0) with the batch size: input_size = [batch_size, …]. Some networks need this dimension for prediction too, so reshape single inputs.

Why not flatten the image into an MLP?

  • A 224×224 RGB image is 150,528 numbers. One dense layer of 1,000 units: 150 million weights.
  • A cat in the top-left and the same cat in the bottom-right share nothing: the MLP must learn the pattern at every position separately.
  • Neighbouring pixels are related, far ones much less: the MLP ignores this structure.

Up to now we only saw fully connected layers. There are smarter, more efficient ways to learn features from formatted data!

Convolutional layers - CNN:

1 / 9
  • The same filter (small, few parameters) is applied throughout the image.
    • Parameter 1 → kernel size ((3,3) in the example).
    • Parameter 2 → stride, the "jump" between calculations ((1,1) here).
    • Parameter 3 → padding (add zeros in the border).
  • The stride and the padding determine the size of the output matrix.
  • A filter "learns" certain features of the input: an edge, a corner, a texture.
$$Z_{ij}=\sum_{u=0}^{F-1}\sum_{v=0}^{F-1}X_{i+u,\,j+v}\,K_{uv}+b$$

Why? With padding the input is $H+2P$ wide. The first window starts at 0 and the last must start at most at $H+2P-F$. Starting points every $S$ steps: $\lfloor(H+2P-F)/S\rfloor+1$ of them.

Convolutional layers - many filters

We can have many filters on a single layer (parameter "filters") to learn multiple features of the formatted data.

  • The input has $C_{\text{in}}$ channels (3 for RGB). Each filter is $F\times F\times C_{\text{in}}$: the third dimension matches the previous layer's automatically.
  • $C_{\text{out}}$ filters → an output with $C_{\text{out}}$ channels ("feature maps").
  • Example: input 7×7×3, two 3×3×3 filters, stride 2 → output 3×3×2.
$$\#\text{params}=(F\cdot F\cdot C_{\text{in}}+1)\cdot C_{\text{out}}$$

3×3 conv, 64 → 128 channels: $(9\cdot64+1)\cdot128=73{,}856$ parameters, whatever the image size.

Weight sharing ⇒ translation equivariance. Shift the input by $(a,b)$, $X'_{ij}=X_{i-a,j-b}$:

$$Z'_{ij}=\sum_{u,v}X_{i-a+u,\,j-b+v}K_{uv}=Z_{i-a,\,j-b}$$

The output shifts by the same amount: a pattern is detected wherever it appears. Pooling then adds a little invariance to small shifts. $\blacksquare$

Stacking convolutional layers: layers close to the input learn low-level features (lines, edges); deeper layers learn higher-order, more abstract features (shapes, objects). Each deeper unit "sees" a larger patch of the image: its receptive field grows.

Pooling layers - CNN:

Down-sampling can be done with the stride: stride (2,2) divides the size by 2 at every conv layer.

A more robust and common approach is a pooling layer (after the non-linear activation).

The pooled feature map is a summarized version of the features detected in the input. Max pooling asks "is the pattern present somewhere in this region?", which tends to be more informative than its average presence.

Basic CNN architecture:

Pooling combined with more filters! The spatial size shrinks while the number of channels grows. Then flatten and classify with dense layers.

How to select the exact hyperparameters? See what has worked for other people solving similar problems! Many reference architectures: LeNet, AlexNet, VGGNet, GoogLeNet, ResNet, ZFNet… millions of parameters to learn.

Famous architectures: AlexNet, VGG, ResNet

AlexNet (2012)

  • First to use ReLU!
  • Won ImageNet LSVRC-2012: 84 % top-5 accuracy (next best 73.8 %).
  • 5 conv layers, overlapped max-pooling, dropout.
  • 62 million trainable variables, 1000 outputs.

VGGNet

  • All conv kernels 3×3, max-pool 2×2 with stride 2.
  • Two 3×3 layers see a 5×5 patch with $2\cdot9=18$ weights instead of 25 (28 % fewer), plus an extra non-linearity.
  • VGG16, VGG19.

ResNet

  • A 56-layer CNN did worse than a 20-layer one, in training too: not overfitting, but vanishing gradients.
  • Skip connections give the gradient a shortcut path.
  • ResNet-18, -34, -50, -101, -152…
$$\bh=F(\bx)+\bx\quad\Rightarrow\quad\frac{\partial\bh}{\partial\bx}=\frac{\partial F}{\partial\bx}+\bI$$

The Jacobian always contains the identity: the gradient reaches early layers even if $F$'s gradient is tiny. It also lets a block learn the identity easily, so a deeper net is at least as good as a shallower one. Inception modules instead run 1×1, 3×3 and 5×5 convolutions in parallel and concatenate them, for features of different sizes.

Transfer learning:

You can use the same neural net as Google, but you do not have the same amount of data!

The first conv layers learn to extract general features from images (edges, textures), so you can reuse that knowledge in new problems:

  • Download a trained net (with the learned weights).
  • Fix (freeze) the first layers, where the complex feature engineering happens.
  • Replace or randomly initialize the last fully connected layers: they learn the more specific, "high-level" features of your problem.
  • Train these (fewer) weights with your (smaller) dataset.

Data augmentation:

  • Flip, rotation, crop: the object can appear anywhere, at any small angle.
  • Colour shift, noise: tolerance to lighting, camera quality.
  • Cut-out (information loss): parts of the object can be hidden.

Only transformations that keep the label! Applied on the fly, a new random version each epoch.

Transpose convolutions:

  • Transposed convolutions are the evolution of classical up-sampling methods.
  • Instead of representing the data in "smaller" (but deeper) dimensions, with transposed convolutions we can expand the dimensions.
  • Controlled by the same parameters: kernel size, strides, padding…

Encoder–decoder shape: shrink the image to a compact "latent" representation, then grow it back. Used for segmentation, autoencoders, image generation.

Image segmentation:

Classify every pixel: road, car, person, sky… or "damage / no damage". The output is a mask as large as the image.

U-Net: an encoder (conv + pooling) to understand what, a decoder (transposed conv) to recover where, and skip connections that copy fine detail.

Loss: pixel-wise cross-entropy (often plus Dice). Metric: IoU between the predicted and true masks:

$$\mathrm{IoU}=\frac{|P\cap G|}{|P\cup G|}$$

  • Classification: what is in the image?
  • Localization: what, and where? One box $(x,y,w,h)$ regressed by the network, plus the class: a loss that combines regression and classification.
  • Detection: all the objects, a box and a class for each.

A prediction matches a true object if their IoU is at least a threshold (often 0.5). Precision, recall and mAP (mean average precision over classes) are then computed as in the ML part.

YOLO: You Only Look Once

A CNN predicts, in one pass, a box, an objectness score and class probabilities for every cell of a grid (dense prediction). That's why it runs in real time.

Post-processing: drop boxes below a confidence threshold, then non-maximum suppression: keep the best box, remove the others that overlap it with IoU above ~0.5, repeat. Lab: fine-tuning YOLO
